将 Linux中的核心网络系统调用按功能生命周期与操作对象划分为以下四大核心类别：
## 一、 基础套接字生命周期
这类系统调用负责网络套接字（Socket）的创建、命名、状态绑定与销毁。 [2] 

* 
* socket()：创建通信端点。指定协议族（如 IPv4、IPv6）和类型（如 TCP、UDP），返回一个文件描述符（fd）。
* bind()：为套接字绑定本地地址。将一个本地 IP 地址和端口号指派给刚创建的套接字。
* listen()：将套接字设为被动监听状态。使该套接字开始接受客户端的连接请求，通常用于服务器端。
* accept() / accept4()：接受客户端的连接。从监听队列中提取一个连接请求，创建一个代表该连接的新套接字。accept4 额外允许在创建时直接设置 SOCK_NONBLOCK（非阻塞）和 SOCK_CLOEXEC 标志。
* connect()：主动向远程主机发起连接。客户端通过此调用向指定的服务器 IP 和端口发起握手。
* close() / shutdown()：关闭或切断套接字通信。close 释放文件描述符；shutdown 则可以只关闭单向通信（如只允许收、不允许发），而不立即释放 fd。 [2, 3, 4, 5] 
* 

## 二、 数据收发（I/O 操作）
用于在已连接或未连接的套接字之间传输数据包，分为基础型、多路复用增强型和异步型。 [2] 
## 1. 面向连接（TCP 等）与无连接（UDP 等）通用收发

* 
* send() / recv()：在已连接的套接字上发送或接收数据（其效果类似于 write/read，但支持网络特有的 flags 参数）。
* sendto() / recvfrom()：在未连接的套接字上收发数据，由于没有建立连接，每次调用都需要在参数中显式指定（或获取）对端的 IP 和端口。 [2] 
* 

## 2. 高级多缓冲区收发（Scatter/Gather I/O）

* 
* sendmsg() / recvmsg()：使用 msghdr 结构体，支持同时发送/接收多块不连续的内存缓冲区，并且能够传输辅助数据（Control Messages/Ancillary Data，如通过 UNIX 域套接字传递文件描述符）。
* sendmmsg() / recvmmsg()：批量（Multiple）数据包收发。允许在一个系统调用中同时发送或接收多个独立的数据包，能有效降低高并发高吞吐网络应用中的上下文切换（Context Switch）开销。
* 

## 三、 配置与元数据获取
用于在运行时查询或修改套接字属性、网卡配置及获取网络连接的元数据。

* 
* setsockopt() / getsockopt()：设置或获取套接字选项。例如调整 TCP 缓冲区大小、开启 SO_REUSEADDR 端口复用、启用 KeepAlive 保活机制等。
* getsockname()：获取套接字自身的本地地址（即当前绑定的本地 IP 和端口）。
* getpeername()：获取套接字所连接的远程对端地址（获取对方的 IP 和端口）。
* ioctl()：设备输入输出控制。在网络领域中，常伴随 SIOCGIFADDR 等宏命令用于配置或读取物理网卡信息（如网卡 IP 地址、子网掩码、MAC 地址或开启混杂模式）。 [6, 7] 
* 

## 四、 现代高性能网络 I/O 增强
Linux 7.0 沿用了以下用于构建高性能网络服务器的核心调用，用于解决传统 select/poll 处理海量套接字时的性能瓶颈。 [6, 8] 

* 
* epoll_create1() / epoll_ctl() / epoll_pwait()：epoll 异步事件通知机制。高并发网络编程（如 Nginx、Redis 内核）的标准基础设施，用来高效监听数万个套接字的读写事件。
* io_uring_setup() / io_uring_enter() / io_uring_register()：零拷贝异步 I/O 框架。现代 Linux 实现完全异步网络 I/O 的杀手锏。应用层通过提交队列（SQ）和完成队列（CQ）与内核共享内存，支持无系统调用损耗（SQPOLL 模式）的极端网络数据流收发。
