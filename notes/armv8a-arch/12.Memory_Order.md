## 内存类型

ARMv8 架构定义了两种互斥的内存类型。所有内存区域都配置为这两种类型中的一种，即 Normal 和 Device。

## 共享域

简介：

Non-shareable：不需要与其它内核、处理器或设备同步的访问；该域通常不用于SMP系统。
Inner Shareable：由几个代理共享的域，但不一定是系统中的所有代理；一个系统可以有几个内部共享域；影响一个内部可共享域的操作不会影响系统中的其他内部可共享域。
Outer Shareable：可以由一个或多个内部可共享域组成；影响外部可共享域的操作也会影响其中的所有内部可共享域。
Full system：整个系统上的操作会影响系统中的所有观察者。

* 非共享（Non-shareable）域
  处于这个域中的内存只由当前CPU核访问，既然只能自己访问，那当然不用考虑跟系统中的其它模块，如其它CPU核或其它设备之间的数据同步问题。所以，如果一个内存区域是非共享的，系统中没有任何硬件会保证其缓存一致性。如果一不小心共享出去了，别的CPU核可以访问了，那必须由软件自己来保证其一致性。
* 内部共享（Inner Shareable）域
  处于这个域中的内存可以由系统中的多个模块同时访问，并且系统硬件保证对于这段内存，对于处于同一个内部共享域中的所有模块，保证缓存一致性。

一个系统中可以同时存在多个内部共享域，对一个内部共享域做出的操作不会影响另外一个内部共享域。

* 外部共享（Outer Shareable）域
  处于这个域中的内存也可以由系统中的多个模块同时访问，并且系统硬件保证对于这段内存，对于处于同一个外部共享域中的所有模块，保证缓存一致性。外部共享域可以包含一个或多个内部共享域，但是一个内部共享域只能属于一个外部共享域，不能被多个外部共享域共享。

对一个外部共享域做出的操作会影响到其包含的所有的内部共享域。

* 全系统共享（Full System）域
  这个很好理解，表示对内存的修改可以被系统中的所有模块都感知到。

在一个具体的系统中，不同域的划分是由硬件平台设计者决定的，不由软件控制。并且，Arm的文档中也没有提及具体要怎么划分。但有一些指导原则，一般在一个操作系统中可以看到的所有CPU核要分配在一个内部域里面，如下图所示：

## 内存屏障

简介：

• 指令同步屏障 (ISB) 会刷流水线, 重新从ICACHE取指令.MMU设置完成后进入虚地址模式需要执行ISB重新取指.

• 数据存储屏障 (DMB) 这防止了跨屏障指令的数据访问指令	的重新排序。保证指令执行顺序,但是不保证完成顺序.

• 数据同步屏障 (DSB) 强制执行与数据存储器屏障相同的顺序,保证完成顺序.

• 指令同步屏障 (ISB) 这用于保证再次获取任何后续指令，以便使用当前 MMU 配置检查特权和访问。它
用于确保任何先前执行的上下文更改操作，例如写入系统控制寄存器，在 ISB 完成时已经完成。例如，
在硬件方面，这可能意味着指令流水线被刷新。它的典型用途是内存管理、缓存控制和上下文切换代
码，或者代码在内存中移动的地方。（*最严格，确保后面的指令从cache或内存重新获取*）

• 数据存储屏障 (DMB) 这防止了跨屏障指令的数据访问指令的重新排序。该处理器在 DMB 之前执行的
所有数据访问，即加载或存储，但不是指令提取，在 DMB 之后的任何数据访问之前，对指定可共享域
内的所有其他主控器都是可见的。（*保证前面的指令先于后面的指令执行，但不能保证前面的指令比后面的指令先执行完*）
（*如果dmb前后的两次访存指令访问的都是同一个终点（比如都是ddr，或者都是spi的fifo），它在能保证两次访问放射顺序的同时，其实就能保证实际的完成顺序了。因为我们访问的是同一个终点，访问路径是一致的，在这种背景下谁先执行谁就先完成。在这种场景下使用DMB相对于DSB就能提升性能。*）

• 数据同步屏障 (DSB) 这强制执行与数据存储器屏障相同的顺序，但具有阻止执行任何进一步指令的额
外效果，而不仅仅是加载或存储，或两者兼而有之，直到同步完成。这可用于防止执行 SEV 指令，例
如，该指令将向其他内核发出事件发生的信号。它一直等到此处理器发出的所有高速缓存、TLB 和分
支预测器维护操作都已针对指定的可共享域完成。（*保证前面指令的内存操作完成后才会执行后面指令*）

│  │  │ NSH   │  Non-Shareable - 只影响当前agent              │  │   │
│  │  └───────┴──────────────────────────────────────────────┘  │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  屏障强度比较:                                                       │
│  • ISB < DMB < DSB                                                  │
│  • ISB: 只保证指令获取顺序                                           │
│  • DMB: 保证数据访问顺序，但不等待完成                                │
│  • DSB: 保证数据访问顺序，且等待所有操作完成                           │
└─────────────────────────────────────────────────────────────────────┘
```

## 屏障指令执行细节

### ISB 指令执行行为

**ISB (Instruction Synchronization Barrier) 是最轻量级的屏障，主要作用于指令获取流水线。**

```
┌─────────────────────────────────────────────────────────────────────┐
│                    ISB Execution Behavior                          │
│                                                                     │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  CPU 微结构行为:                                             │   │
│  │                                                             │   │
│  │  1. 指令获取阶段 (Fetch Stage):                              │   │
│  │     ┌───────────────────────────────────────────────────┐   │   │
│  │     │  • 立即刷新指令预取队列 (Prefetch Queue)           │   │   │
│  │     │  • 清空指令缓冲区 (Instruction Buffer)             │   │   │
│  │     │  • 丢弃已预取但未执行的指令                        │   │   │
│  │     └───────────────────────────────────────────────────┘   │   │
│  │                                                             │   │
│  │  2. 指令解码阶段 (Decode Stage):                           │   │
│  │     ┌───────────────────────────────────────────────────┐   │   │
│  │     │  • 清空解码队列 (Decode Queue)                     │   │   │
│  │     │  • 丢弃已解码但未发射的微指令                      │   │   │
│  │     └───────────────────────────────────────────────────┘   │   │
│  │                                                             │   │
│  │  3. 指令分发阶段 (Dispatch Stage):                        │   │
│  │     ┌───────────────────────────────────────────────────┐   │   │
│  │     │  • 阻止后续指令分发到执行单元                       │   │   │
│  │     │  • 清空分发队列 (Dispatch Queue)                    │   │   │
│  │     │  • 等待所有已分发指令执行完成                       │   │   │
│  │     └───────────────────────────────────────────────────┘   │   │
│  │                                                             │   │
│  │  4. 系统寄存器同步:                                       │   │
│  │     ┌───────────────────────────────────────────────────┐   │   │
│  │     │  • 确保之前对系统寄存器的写入已生效                 │   │   │
│  │     │  • 确保当前 EL 级别的 MMU/TLB 配置已更新           │   │   │
│  │     │  • 确保 PSTATE 标志位更新已完成                     │   │   │
│  │     └───────────────────────────────────────────────────┘   │   │
│  │                                                             │   │
│  │  5. 重新取指:                                               │   │
│  │     ┌───────────────────────────────────────────────────┐   │   │
│  │     │  • ISB 完成后，从当前 PC 重新获取指令              │   │   │
│  │     │  • 使用最新的 MMU/TLB 配置进行地址翻译             │   │   │
│  │     │  • 从 I-Cache 或内存重新读取指令                   │   │   │
│  │     └───────────────────────────────────────────────────┘   │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  AXI 总线行为:                                              │   │
│  │                                                             │   │
│  │  ┌─────────────────────────────────────────────────────────┐│   │
│  │  │  • ISB 不产生任何 AXI 总线事务                          ││   │
│  │  │  • 不等待任何待处理的总线事务完成                        ││   │
│  │  │  • 不发送任何同步信号到互联设备                          ││   │
│  │  │  • 对 D-Cache/写缓冲区无任何影响                        ││   │
│  │  └─────────────────────────────────────────────────────────┘│   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  仲裁机构行为:                                              │   │
│  │                                                             │   │
│  │  ┌─────────────────────────────────────────────────────────┐│   │
│  │  │  • ISB 不参与总线仲裁                                   ││   │
│  │  │  • 不改变当前 CPU 在仲裁器中的优先级                     ││   │
│  │  │  • 不产生任何仲裁请求或响应                              ││   │
│  │  │  • 不影响其他 master 的总线访问                         ││   │
│  │  └─────────────────────────────────────────────────────────┘│   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  ISB 执行时序:                                                       │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  Time →                                                      │   │
│  │                                                             │   │
│  │  ┌────┬────┬────┬────┬────┬────┬────┬────┬────┬────┬────┐   │   │
│  │  │ T0 │ T1 │ T2 │ T3 │ T4 │ T5 │ T6 │ T7 │ T8 │ T9 │ T10│   │   │
│  │  └──┬─┴──┬─┴──┬─┴──┬─┴──┬─┴──┬─┴──┬─┴──┬─┴──┬─┴──┬─┴──┬─┘   │   │
│  │     │    │    │    │    │    │    │    │    │    │    │       │   │
│  │     ▼    ▼    ▼    ▼    ▼    ▼    ▼    ▼    ▼    ▼    ▼       │   │
│  │  ┌────────────────────────────────────────────────────────┐   │   │
│  │  │ ISB 取指 → 解码 → 发射 → 流水线清空 → 重新取指 → 继续   │   │   │
│  │  └────────────────────────────────────────────────────────┘   │   │
│  │                                                             │   │
│  │  关键特性:                                                     │   │
│  │  • ISB 是最快的屏障，仅影响指令流水线                         │   │
│  │  • 不涉及数据访问或总线操作                                   │   │
│  │  • 执行延迟通常为几个周期（取决于流水线深度）                   │   │
│  └─────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────┘
```

**ISB 典型使用场景:**

| 场景 | 说明 |
|------|------|
| MMU 配置后 | 修改 TTBR/MAIR/TCR 后，需要 ISB 使新配置生效 |
| 异常等级切换 | 切换 EL 后，需要 ISB 使用新等级的配置 |
| 指令自修改 | 代码修改自身后，需要 ISB 刷新指令缓存 |
| 缓存维护后 | 执行 IC IVAU 等指令后，需要 ISB 重新取指 |

### DMB 指令执行行为

**DMB (Data Memory Barrier) 是中等强度的屏障，主要作用于数据访问的排序。**

```
┌─────────────────────────────────────────────────────────────────────┐
│                    DMB Execution Behavior                          │
│                                                                     │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  CPU 微结构行为:                                             │   │
│  │                                                             │   │
│  │  1. 指令分发暂停:                                          │   │
│  │     ┌───────────────────────────────────────────────────┐   │   │
│  │     │  • 阻止分发 DMB 之后的数据访问指令到执行单元        │   │   │
│  │     │  • 允许非数据访问指令继续分发执行                   │   │   │
│  │     │  • 允许 DMB 之前的指令继续分发执行                 │   │   │
│  │     └───────────────────────────────────────────────────┘   │   │
│  │                                                             │   │
│  │  2. 写缓冲区管理:                                          │   │
│  │     ┌───────────────────────────────────────────────────┐   │   │
│  │     │  • 确保写缓冲区中 DMB 之前的数据写入队列            │   │   │
│  │     │  • 不等待写缓冲区刷新完成                          │   │   │
│  │     │  • 允许写缓冲区继续向内存传输数据                   │   │   │
│  │     └───────────────────────────────────────────────────┘   │   │
│  │                                                             │   │
│  │  3. 缓存操作排序:                                          │   │
│  │     ┌───────────────────────────────────────────────────┐   │   │
│  │     │  • 确保 DMB 之前的缓存操作 (DC/ZVA) 已发出          │   │   │
│  │     │  • 确保 DMB 之后的缓存操作等待排序完成              │   │   │
│  │     │  • 不等待缓存操作实际完成                           │   │   │
│  │     └───────────────────────────────────────────────────┘   │   │
│  │                                                             │   │
│  │  4. 指令重排序抑制:                                        │   │
│  │     ┌───────────────────────────────────────────────────┐   │   │
│  │     │  • 阻止 DMB 之前的数据访问越过 DMB 向后重排序       │   │   │
│  │     │  • 阻止 DMB 之后的数据访问越过 DMB 向前重排序       │   │   │
│  │     │  • 允许 DMB 之前的指令之间继续重排序                 │   │   │
│  │     │  • 允许 DMB 之后的指令之间继续重排序                 │   │   │
│  │     └───────────────────────────────────────────────────┘   │   │
│  │                                                             │   │
│  │  5. 乱序执行窗口:                                          │   │
│  │     ┌───────────────────────────────────────────────────┐   │   │
│  │     │  • 非数据访问指令（如算术、逻辑）可继续乱序执行      │   │   │
│  │     │  • DMB 不影响指令级并行 (ILP)                       │   │   │
│  │     │  • 分支预测和推测执行不受影响                        │   │   │
│  │     └───────────────────────────────────────────────────┘   │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  AXI 总线行为:                                              │   │
│  │                                                             │   │
│  │  ┌─────────────────────────────────────────────────────────┐│   │
│  │  │  • 不产生独立的 AXI 总线事务                           ││   │
│  │  │  • 不强制等待待处理总线事务完成                         ││   │
│  │  │                                                         ││   │
│  │  │  • 根据选项影响总线排序:                                ││   │
│  │  │    ├─ DMB SY: 全系统范围排序                           ││   │
│  │  │    ├─ DMB ISH: Inner Shareable 域排序                  ││   │
│  │  │    ├─ DMB OSH: Outer Shareable 域排序                  ││   │
│  │  │    ├─ DMB NSH: Non-Shareable 域排序                    ││   │
│  │  │    ├─ DMB LD: 仅 Load 操作排序                         ││   │
│  │  │    └─ DMB ST: 仅 Store 操作排序                        ││   │
│  │  │                                                         ││   │
│  │  │  • 对 AXI 信号的影响:                                   ││   │
│  │  │    ├─ ARVALID/AWVALID: 不强制立即拉高                   ││   │
│  │  │    ├─ ARREADY/AWREADY: 不影响                          ││   │
│  │  │    ├─ WVALID: 不强制立即拉高                           ││   │
│  │  │    └─ BVALID/RVALID: 不等待响应                        ││   │
│  │  └─────────────────────────────────────────────────────────┘│   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  仲裁机构行为:                                              │   │
│  │                                                             │   │
│  │  ┌─────────────────────────────────────────────────────────┐│   │
│  │  │  • DMB 不直接参与总线仲裁                               ││   │
│  │  │  • 不产生仲裁请求信号                                   ││   │
│  │  │  • 不改变仲裁优先级                                     ││   │
│  │  │  • 不阻塞其他 master 的总线访问                         ││   │
│  │  │                                                         ││   │
│  │  │  • 间接触发排序:                                        ││   │
│  │  │    ├─ 通过控制写缓冲区发射顺序                          ││   │
│  │  │    ├─ 通过控制缓存操作发出顺序                          ││   │
│  │  │    └─ 通过控制后续指令发射时机                          ││   │
│  │  └─────────────────────────────────────────────────────────┘│   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  DMB 执行时序:                                                       │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  Time →                                                      │   │
│  │                                                             │   │
│  │  ┌────┬────┬────┬────┬────┬────┬────┬────┬────┬────┬────┐   │   │
│  │  │ T0 │ T1 │ T2 │ T3 │ T4 │ T5 │ T6 │ T7 │ T8 │ T9 │ T10│   │   │
│  │  └──┬─┴──┬─┴──┬─┴──┬─┴──┬─┴──┬─┴──┬─┴──┬─┴──┬─┴──┬─┴──┬─┘   │   │
│  │     │    │    │    │    │    │    │    │    │    │    │       │   │
│  │     ▼    ▼    ▼    ▼    ▼    ▼    ▼    ▼    ▼    ▼    ▼       │   │
│  │  ┌────────────────────────────────────────────────────────┐   │   │
│  │  │ STR → STR → DMB → [排序完成] → LDR → LDR → 继续执行     │   │   │
│  │  │      │         │                  │                      │   │   │
│  │  │      ▼         ▼                  ▼                      │   │   │
│  │  │  写缓冲区    暂停后续            恢复指令                  │   │   │
│  │  │  继续传输    数据访问            发射                      │   │   │
│  │  └────────────────────────────────────────────────────────┘   │   │
│  │                                                             │   │
│  │  关键特性:                                                     │   │
│  │  • DMB 只保证顺序，不保证完成                                 │   │
│  │  • 执行开销中等，约几个到十几个周期                           │   │
│  │  • 不阻塞非数据访问指令的执行                                 │   │
│  │  • 是实现无锁同步的基础指令                                   │   │
│  └─────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────┘
```

**DMB 选项详细说明:**

| 选项 | 排序范围 | 适用场景 |
|------|----------|----------|
| SY | Load-Load, Load-Store, Store-Load, Store-Store | 最严格，用于跨域同步 |
| ISH | 同 SY，仅限 Inner Shareable 域 | SMP 多核心同步 |
| ISHST | 仅限 Store-Store | 发布操作（Release） |
| ISHLD | 仅限 Load-Load/Load-Store | 获取操作（Acquire） |
| OSH | 同 SY，仅限 Outer Shareable 域 | 跨 Cluster 同步 |
| OSHST | 仅限 Store-Store | 跨 Cluster 发布操作 |
| OSHLD | 仅限 Load-Load/Load-Store | 跨 Cluster 获取操作 |
| NSH | 同 SY，仅限 Non-Shareable 域 | 单核心内排序 |

### DSB 指令执行行为

**DSB (Data Synchronization Barrier) 是最强的屏障，等待所有先前操作完成。**

```
┌─────────────────────────────────────────────────────────────────────┐
│                    DSB Execution Behavior                          │
│                                                                     │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  CPU 微结构行为:                                             │   │
│  │                                                             │   │
│  │  1. 指令分发阻塞:                                          │   │
│  │     ┌───────────────────────────────────────────────────┐   │   │
│  │     │  • 阻止所有后续指令分发到执行单元                   │   │   │
│  │     │  • DSB 之后的所有指令必须等待 DSB 完成              │   │   │
│  │     │  • 包括算术、逻辑、分支等所有类型指令                │   │   │
│  │     └───────────────────────────────────────────────────┘   │   │
│  │                                                             │   │
│  │  2. 写缓冲区刷新:                                          │   │
│  │     ┌───────────────────────────────────────────────────┐   │   │
│  │     │  • 等待写缓冲区中所有数据写入完成                    │   │   │
│  │     │  • 等待写确认 (B-Channel) 全部返回                  │   │   │
│  │     │  • 确保所有脏缓存行写回内存                          │   │   │
│  │     │  • 清空整个写缓冲区                                 │   │   │
│  │     └───────────────────────────────────────────────────┘   │   │
│  │                                                             │   │
│  │  3. 缓存操作完成:                                          │   │
│  │     ┌───────────────────────────────────────────────────┐   │   │
│  │     │  • 等待所有 DC 指令完成 (CIVAC, CVAC, IVAC 等)      │   │   │
│  │     │  • 等待所有 IC 指令完成 (IALLU, IVAU 等)            │   │   │
│  │     │  • 等待所有 ZVA (Zero VA) 指令完成                  │   │   │
│  │     │  • 等待所有 TLB 维护指令完成                        │   │   │
│  │     └───────────────────────────────────────────────────┘   │   │
│  │                                                             │   │
│  │  4. 流水线清空:                                            │   │
│  │     ┌───────────────────────────────────────────────────┐   │   │
│  │     │  • 等待所有已发射指令执行完成                       │   │   │
│  │     │  • 等待所有执行单元空闲                             │   │   │
│  │     │  • 确保没有进行中的内存访问                         │   │   │
│  │     └───────────────────────────────────────────────────┘   │   │
│  │                                                             │   │
│  │  5. 系统操作同步:                                          │   │
│  │     ┌───────────────────────────────────────────────────┐   │   │
│  │     │  • 等待所有 SEV/SEVL/WFE/WFI 指令完成              │   │   │
│  │     │  • 等待所有 HINT 指令完成                           │   │   │
│  │     │  • 确保所有系统寄存器写入已生效                     │   │   │
│  │     └───────────────────────────────────────────────────┘   │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  AXI 总线行为:                                              │   │
│  │                                                             │   │
│  │  ┌─────────────────────────────────────────────────────────┐│   │
│  │  │  • 产生 AXI 同步事务 (Barrier Transaction)              ││   │
│  │  │  • 等待所有待处理总线事务完成                           ││   │
│  │  │                                                         ││   │
│  │  │  AXI4 信号行为:                                         ││   │

│  │                                                             │   │
│  │  关键特性:                                                     │   │
│  │  • DSB 是最慢的屏障，等待所有操作完成                         │   │
│  │  • 执行开销大，可能需要几十个甚至上百个周期                   │   │
│  │  • 阻塞所有后续指令执行                                       │   │
│  │  • 用于确保数据真正写入内存后再执行后续操作                   │   │

└─────────────────────────────────────────────────────────────────────┘

**DSB 典型使用场景:**

| 场景 | 说明 |
|------|------|
| DMA 操作前 | CPU 写入 DMA 缓冲区后，DSB 确保数据已写入内存 |
| 中断使能前 | 清除中断源后，DSB 确保清除操作完成后再使能中断 |
| 电源管理 | 进入低功耗模式前，DSB 确保所有操作完成 |
| 系统复位前 | 复位前使用 DSB 确保所有挂起操作完成 |
| SEV 指令前 | 发送事件通知前，DSB 确保数据对其他核心可见 |

│  │                                                             │   │

│  │  │  • 屏障开销: 低到中                                     │   │   │

│  │                                                             │   │

│  │  ┌─────────────────────────────────────────────────────┐   │   │
│  │  │  • 自动按序执行，不需要屏障                              │   │   │
│  │  │  • 每次访问都是原子的、顺序的                            │   │   │
│  │  │  • 性能最差，但最安全                                   │   │   │
│  │  └─────────────────────────────────────────────────────┘   │   │
│  └─────────────────────────────────────────────────────────────┘   │

│  └─────────────────────────────────────────────────────────────┘   │
