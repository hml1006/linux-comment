# lockdep — 锁调试

## 概述

lockdep 是 Linux 内核的运行时锁正确性验证工具，用于检测锁使用中的各种问题，如死锁、锁顺序反转、递归加锁、中断上下文误用等。lockdep 通过追踪锁的获取顺序，构建锁依赖图，在运行时验证锁的使用正确性。

## 核心数据结构

### lock_class

```
struct lock_class {
    struct hlist_node        hash_entry;       /* 哈希表条目 */
    struct list_head         lock_entry;       /* 所有锁类链表 */
    struct list_head         locks_after;      /* 之后获取的锁 */
    struct list_head         locks_before;     /* 之前获取的锁 */
    const struct lockdep_subclass_key *key;    /* 锁类键 */
    lock_cmp_fn              cmp_fn;           /* 比较函数 */
    lock_print_fn            print_fn;         /* 打印函数 */
    unsigned int             subclass;         /* 子类 */
    unsigned int             dep_gen_id;       /* 依赖生成 ID */
    unsigned long            usage_mask;       /* 使用掩码 */
    const struct lock_trace  *usage_traces[LOCK_TRACE_STATES]; /* 使用追踪 */
    const char               *name;            /* 锁名称 */
    int                      name_version;     /* 名称版本 */
    u8                       wait_type_inner;  /* 内部等待类型 */
    u8                       wait_type_outer;  /* 外部等待类型 */
    u8                       lock_type;        /* 锁类型 */
};
```

### lockdep_map

```
struct lockdep_map {
    struct lock_class_key    *key;             /* 锁类键 */
    struct lock_class        *class_cache[NR_LOCKDEP_CACHING_CLASSES]; /* 缓存 */
    const char               *name;            /* 锁名称 */
    u8                       wait_type_outer;  /* 外部等待类型 */
    u8                       wait_type_inner;  /* 内部等待类型 */
    u8                       lock_type;        /* 锁类型 */
};
```

### held_lock

```
struct held_lock {
    u64                      prev_chain_key;   /* 前一个依赖链哈希 */
    unsigned long            acquire_ip;       /* 获取锁的指令地址 */
    struct lockdep_map       *instance;        /* 锁实例 */
    struct lockdep_map       *nest_lock;       /* 嵌套锁 */
    unsigned int             class_idx:MAX_LOCKDEP_KEYS_BITS; /* 类索引 */
    /* 中断上下文标记 */
    unsigned int             irq_context:2;    /* IRQ 上下文 */
    unsigned int             hardirq_context:1; /* 硬中断上下文 */
    unsigned int             softirq_context:1; /* 软中断上下文 */
};
```

### lock_list

```
struct lock_list {
    struct list_head         entry;            /* 链表条目 */
    struct lock_class        *class;           /* 当前锁类 */
    struct lock_class        *links_to;        /* 指向的锁类 */
    const struct lock_trace  *trace;           /* 追踪信息 */
    u16                      distance;         /* 距离 */
    u8                       dep;              /* 依赖位图 */
    u8                       only_xr;          /* BFS 标记 */
    struct lock_list         *parent;          /* BFS 父节点 */
};
```

## 等待类型

| 类型 | 枚举值 | 说明 |
|------|--------|------|
| LD_WAIT_INV | 0 | 未检查 |
| LD_WAIT_FREE | 1 | 无等待（RCU等） |
| LD_WAIT_SPIN | 2 | 自旋等待（raw_spinlock） |
| LD_WAIT_CONFIG | 3 | 可配置（spinlock_t） |
| LD_WAIT_SLEEP | 4 | 睡眠等待（mutex） |

## 锁获取流程

```
┌─────────────────────────────────────────────────────────────────────┐
│                    Lock Acquisition Flow                        │
│                                                                     │
│  __lock_acquire():                                                  │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  1. 获取当前任务的 lockdep 上下文                           │   │
│  │  2. 检查是否递归加锁                                       │   │
│  │  3. 查找或创建 lock_class                                  │   │
│  │  4. 检查中断上下文                                         │   │
│  │  5. 检查等待类型兼容性                                     │   │
│  │  6. 检测死锁风险 (BFS 循环检测)                            │   │
│  │  7. 更新依赖链哈希                                         │   │
│  │  8. 添加锁到当前持锁列表                                   │   │
│  │  9. 更新锁依赖图                                           │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  关键检查点:                                                         │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  • check_deadlock() - 死锁检测                             │   │
│  │  • check_usage() - 使用上下文检查                           │   │
│  │  • check_nesting() - 嵌套检查                               │   │
│  │  • check_wait_types() - 等待类型检查                        │   │
│  └─────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────┘
```

## 死锁检测算法

### BFS 循环检测

```
┌─────────────────────────────────────────────────────────────────────┐
│                    Cycle Detection (BFS)                        │
│                                                                     │
│  check_deadlock():                                                  │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  输入: 要获取的锁 new_class, 当前持有的锁列表                 │   │
│  │                                                             │   │
│  │  对于每个已持有的锁 held_class:                              │   │
│  │    ┌─────────────────────────────────────────────────────┐   │   │
│  │    │  1. 检查是否已有 held_class → new_class 的依赖       │   │   │
│  │    │     如果有 → 跳过（已验证）                           │   │   │
│  │    │                                                     │   │   │
│  │    │  2. 检查是否存在 new_class → ... → held_class 的路径 │   │   │
│  │    │     如果存在 → 检测到循环依赖 → 报告死锁风险          │   │   │
│  │    │                                                     │   │   │
│  │    │  3. 如果不存在 → 添加 held_class → new_class 依赖   │   │   │
│  │    └─────────────────────────────────────────────────────┘   │   │
│  │                                                             │   │
│  │  BFS 实现:                                                  │   │
│  │  ┌─────────────────────────────────────────────────────┐   │   │
│  │  │  queue = {new_class}                                 │   │   │
│  │  │  visited = {}                                        │   │   │
│  │  │  while queue not empty:                              │   │   │
│  │  │    current = dequeue()                               │   │   │
│  │  │    for each lock in current->locks_after:            │   │   │
│  │  │      if lock == held_class:                          │   │   │
│  │  │        return TRUE (循环存在)                        │   │   │
│  │  │      if lock not in visited:                         │   │   │
│  │  │        enqueue(lock)                                 │   │   │
│  │  │        visited.add(lock)                             │   │   │
│  │  │  return FALSE (无循环)                               │   │   │
│  │  └─────────────────────────────────────────────────────┘   │   │
│  └─────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────┘
```

## 检测规则

### 锁顺序反转检测

```
┌─────────────────────────────────────────────────────────────────────┐
│                    Lock Order Inversion Detection               │
│                                                                     │
│  场景:                                                              │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  线程 A: lock(A) → lock(B)                                  │   │
│  │  线程 B: lock(B) → lock(A)                                  │   │
│  │  结果: 死锁                                                  │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  lockdep 检测:                                                      │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  1. 线程 A 获取 A → 添加依赖 A→B                             │   │
│  │  2. 线程 B 获取 B → 检查 B→A 是否形成循环                    │   │
│  │  3. BFS 检测到 B→A 的路径已存在                              │   │
│  │  4. 报告锁顺序反转                                            │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  报告示例:                                                          │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  ==========================================================│   │
│  │  WARNING: possible circular locking dependency             │   │
│  │  ----------------------------------------------------------│   │
│  │  lock_A (0x12340000) is taken first                      │   │
│  │  lock_B (0x56780000) is taken second                     │   │
│  │  ----------------------------------------------------------│   │
│  │  but in another context:                                  │   │
│  │  lock_B is taken first                                    │   │
│  │  lock_A is taken second                                   │   │
│  │  ==========================================================│   │
│  └─────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────┘
```

### 中断上下文检测

```
┌─────────────────────────────────────────────────────────────────────┐
│                    IRQ Context Detection                       │
│                                                                     │
│  lockdep 追踪三种上下文:                                             │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  • process context (进程上下文)                            │   │
│  │  • hardirq context (硬中断上下文)                          │   │
│  │  • softirq context (软中断上下文)                          │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  检测规则:                                                          │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  • 在硬中断中获取的锁不能在进程上下文中获取                  │   │
│  │  • 在软中断中获取的锁不能在进程上下文中获取                  │   │
│  │  • 在硬中断中获取的锁可以在软中断中获取（反之不行）          │   │
│  │  • 互斥锁不能在中断上下文中获取                             │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  检测示例:                                                          │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  ==========================================================│   │
│  │  WARNING: lock held in interrupt context                   │   │
│  │  ----------------------------------------------------------│   │
│  │  lock_A was acquired in hardirq context                   │   │
│  │  but is now being acquired in process context             │   │
│  │  ==========================================================│   │
│  └─────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────┘
```

### 等待类型检测

```
┌─────────────────────────────────────────────────────────────────────┐
│                    Wait Type Detection                         │
│                                                                     │
│  检测规则:                                                          │
```

## API 接口

### 锁标记

```c
DEFINE_LOCKDEP_CLASS(key);           /* 定义锁类键 */
lockdep_init_map(&lock->dep_map, name, key, subclass); /* 初始化锁映射 */
```

### 上下文控制

```c
lockdep_off();                       /* 关闭 lockdep 检测 */
lockdep_on();                        /* 开启 lockdep 检测 */
lockdep_set_novalidate_class(key);   /* 设置不验证的锁类 */
lockdep_set_notrack_class(key);      /* 设置不追踪的锁类 */
```

### 断言

```c
lockdep_assert_held(lock);           /* 断言锁已持有 */
lockdep_assert_held_write(lock);     /* 断言写锁已持有 */
lockdep_assert_held_read(lock);      /* 断言读锁已持有 */
lockdep_assert_not_held(lock);       /* 断言锁未持有 */
```

## 常见问题

### 误报处理

```
┌─────────────────────────────────────────────────────────────────────┐

│                                                                     │
│  原因:                                                              │
│  ┌─────────────────────────────────────────────────────────────┐   │

│  └─────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────┘
```

## 总结

lockdep 是一个强大的锁调试工具：

1. **运行时验证**：在运行时检测锁使用问题
2. **依赖图构建**：自动构建锁依赖关系图
3. **循环检测**：使用 BFS 算法检测死锁风险
4. **上下文追踪**：检测中断上下文误用
5. **详细报告**：提供完整的问题上下文

lockdep 在开发和测试阶段非常有用，但由于性能开销较大，通常不在生产环境启用。
