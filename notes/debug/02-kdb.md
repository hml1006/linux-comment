# KDB — 内核内置调试器

## 概述

KDB (Kernel Debugger) 是 Linux 内核内置的命令行调试器，允许开发者在系统运行时进行交互式调试。KDB 可以在内核崩溃时自动启动，也可以通过 SysRq-g 手动触发。

## 核心数据结构

### kdb_cmd

```
struct kdb_cmd {
    struct list_head        list;           /* 命令链表 */
    const char              *name;          /* 命令名称 */
    const char              *usage;         /* 使用说明 */
    const char              *help;          /* 帮助信息 */
    kdb_func_t              func;           /* 命令处理函数 */
    kdb_cmdflags_t          flags;          /* 命令标志 */
    const char              *cmdgrp;        /* 命令组 */
};
```

每个 KDB 命令都通过该结构注册到命令链表中。

### kdb_state

```
unsigned int kdb_flags;          /* KDB 状态标志 */
int kdb_initial_cpu;             /* 拥有 KDB 的 CPU */
int kdb_nextline;                /* 下一行标志 */
int kdb_state;                   /* 通用 KDB 状态 */

struct task_struct *kdb_current_task;   /* 当前任务 */
struct pt_regs *kdb_current_regs;       /* 当前寄存器 */
```

这些全局变量管理 KDB 的运行状态。

### kdb_exceptioninfo

```
struct kdb_exceptioninfo {
    int                     ex_vector;      /* 异常向量 */
    int                     signo;          /* 信号号 */
    int                     err_code;       /* 错误码 */
    struct pt_regs          *regs;          /* 寄存器 */
};
```

保存异常信息。

## 断点管理

### 断点结构

```
struct kdb_bp {
    struct list_head        list;           /* 断点链表 */
    unsigned long           bp_addr;        /* 断点地址 */
    unsigned char           bp_insn[8];     /* 保存的原始指令 */
    int                     bp_type;        /* 断点类型 */
    int                     bp_task;        /* 目标任务 */
    int                     bp_cpu;         /* 目标 CPU */
    unsigned long           bp_flags;       /* 断点标志 */
};
```

### 断点操作流程

```
┌─────────────────────────────────────────────────────────────────────┐
│                    Breakpoint Management                          │
│                                                                     │
│  设置断点 (bp):                                                      │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  1. 解析地址参数                                            │   │
│  │  2. 检查是否已存在相同断点                                    │   │
│  │  3. 保存原始指令到 bp_insn[]                                 │   │
│  │  4. 替换为断点指令 (ARM: brk #0xf000)                        │   │
│  │  5. 刷新指令缓存 (flush_icache_range)                       │   │
│  │  6. 添加到断点链表                                          │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                           │                                         │
│                           ▼                                         │
│  触发断点:                                                          │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  1. CPU 执行断点指令触发异常                                 │   │
│  │  2. kgdb_handle_exception() 捕获异常                        │   │
│  │  3. 查找断点链表匹配地址                                    │   │
│  │  4. 恢复原始指令                                            │   │
│  │  5. 进入 KDB 命令行                                          │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                           │                                         │
│                           ▼                                         │
│  删除断点 (bc):                                                      │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  1. 查找断点链表                                            │   │
│  │  2. 恢复原始指令                                            │   │
│  │  3. 刷新指令缓存                                            │   │
│  │  4. 从链表中删除                                            │   │
│  └─────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────┘
```

## 堆栈追踪

### 核心函数

```
int kdb_bt(struct pt_regs *regs, int argc, const char **argv)
```

该函数执行以下操作：
1. 获取当前任务的栈指针
2. 遍历栈帧，提取返回地址
3. 使用 kallsyms 解析函数名
4. 显示函数调用链

### 堆栈格式

```
void kdb_md(void)          /* 内存转储 */

```

这些命令支持各种寻址模式和显示格式。

## 权限控制

### Lockdown 状态

```
static void kdb_check_for_lockdown(void)
```

检查安全 lockdown 状态，限制调试命令的权限：
- READ_ONLY 模式：禁止内存写、寄存器写、流程控制命令
- FULL 模式：仅允许 INSPECT、SIGNAL、REBOOT 命令

### 权限检查

```
static bool kdb_check_flags(kdb_cmdflags_t flags, int permissions, bool no_args)
```

检查命令标志、权限和 lockdown 状态是否允许执行命令。

## 进入方式

| 方式 | 说明 |
|------|------|
| 内核崩溃 | 自动进入 KDB |
| SysRq-g | 按住 Alt+SysRq+g |
| kdb_breakpoint() | 代码中主动调用 |
| 硬件断点 | 通过硬件调试寄存器触发 |
| 内核参数 | kgdbwait 启动时等待 |

## 编译配置

| 配置项 | 说明 |
|--------|------|
| CONFIG_KDB | 启用 KDB |
| CONFIG_KDB_DEFAULT_ENABLE | 默认启用命令 |
| CONFIG_KDB_CONTINUE_CATASTROPHIC | 灾难性错误后继续 |
| CONFIG_KDB_KEYBOARD | 键盘支持 |

## 使用示例

```
# 进入 KDB
echo g > /proc/sysrq-trigger

# 查看帮助
kdb> help

# 查看堆栈
kdb> bt

# 查看内存
kdb> md ffffff80081d2400

# 设置断点
kdb> bp my_function

# 列出断点
kdb> bl

# 删除断点
kdb> bc 1

# 继续执行
kdb> go

# 查看进程列表
kdb> ps

# 查看寄存器
kdb> rd

# 切换 CPU
kdb> cpu 1
```

## 总结

KDB 是一个轻量级的内核调试器，提供了基本的调试功能：

1. **堆栈追踪**：查看函数调用链
2. **内存操作**：读取和修改内存
3. **断点管理**：设置、查看和删除断点
4. **寄存器访问**：查看和修改寄存器
5. **任务管理**：查看进程列表
6. **系统控制**：继续执行、重启系统

KDB 的优点是启动快、占用资源少，适合内核崩溃后的初步分析。对于复杂调试场景，建议配合 KGDB 使用。
