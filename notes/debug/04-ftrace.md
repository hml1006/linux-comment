# ftrace — 函数追踪系统

## 概述

ftrace 是 Linux 内核提供的一个强大的函数追踪系统，允许开发者在内核运行时追踪函数的调用、执行时间和调用关系。ftrace 支持多种追踪方式，包括函数入口/出口追踪、函数调用图、事件追踪等。

## 核心数据结构

### ftrace_ops

```
struct ftrace_ops {
    ftrace_func_t            func;           /* 追踪回调函数 */
    unsigned long            flags;          /* 操作标志 */
    struct ftrace_hash       *func_hash;     /* 函数哈希表 */
    struct list_head         subop_list;     /* 子操作列表 */
    struct ftrace_ops        *next;          /* 链表指针 */
};
```

该结构定义了一个追踪操作，包含回调函数和过滤规则。

### ftrace_regs

```
struct ftrace_regs {
    struct pt_regs           *regs;          /* 完整寄存器 */
    unsigned long            ip;             /* 指令指针 */
    unsigned long            parent_ip;      /* 父函数 IP */
    unsigned long            flags;          /* 标志位 */
};
```

存储函数入口/出口时的寄存器状态。

### trace_array

```
struct trace_array {
    struct ring_buffer       *buffer;        /* 环形缓冲区 */
    struct trace_event_file  *events;        /* 事件文件 */
    struct trace_seq         seq;            /* 序列输出 */
    int                      cpu;            /* CPU 编号 */
    unsigned long            trace_flags;    /* 追踪标志 */
};
```

追踪数组，管理追踪数据的存储和输出。

### ring_buffer

```
struct ring_buffer {
    struct ring_buffer_per_cpu *per_cpu;     /* 每 CPU 缓冲区 */
    unsigned long            size;           /* 缓冲区大小 */
    int                      nr_cpus;        /* CPU 数量 */
    unsigned long            commit_overrun; /* 提交溢出计数 */
};
```

高性能环形缓冲区，用于存储追踪数据。

## 函数插桩机制

### 编译时插桩

```
┌─────────────────────────────────────────────────────────────────────┐
│                    Compile-Time Instrumentation                   │
│                                                                     │
│  gcc -pg 选项:                                                      │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  在每个函数入口插入:                                         │   │
│  │  call ftrace_caller                                         │   │
│  │                                                             │   │
│  │  原始代码:                                                   │   │
│  │  my_function:                                               │   │
│  │      pushq %rbp                                             │   │
│  │      movq %rsp, %rbp                                        │   │
│  │      ...                                                    │   │
│  │                                                             │   │
│  │  插桩后:                                                     │   │
│  │  my_function:                                               │   │
│  │      call ftrace_caller                                     │   │
│  │      pushq %rbp                                             │   │
│  │      movq %rsp, %rbp                                        │   │
│  │      ...                                                    │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  ftrace_caller:                                                     │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  1. 保存寄存器状态                                          │   │
│  │  2. 获取当前 IP 和父 IP                                     │   │
│  │  3. 调用 ftrace_ops_list_func()                             │   │
│  │  4. 根据 ftrace_ops 列表调用各个追踪函数                    │   │
│  │  5. 恢复寄存器状态                                          │   │
│  │  6. 返回原函数继续执行                                      │   │
│  └─────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────┘
```

### 动态 ftrace (Dynamic ftrace)

```
┌─────────────────────────────────────────────────────────────────────┐
│                    Dynamic ftrace                                │
│                                                                     │
│  原理:                                                              │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  1. 编译时在函数入口插入 NOP 指令                           │   │
│  │  2. 运行时通过修改指令将 NOP 替换为跳转指令                 │   │
│  │  3. 跳转指令指向 ftrace_caller                             │   │
│  │  4. 禁用时再将跳转指令还原为 NOP                           │   │
│  │  5. 使用 stop_machine 确保修改的原子性                    │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  指令修改流程:                                                      │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  禁用状态:                                                   │   │
│  │  my_function:                                               │   │
│  │      nop                                                     │   │
│  │      pushq %rbp                                             │   │
│  │      ...                                                    │   │
│  │                                                             │   │
│  │  启用状态:                                                   │   │
│  │  my_function:                                               │   │
│  │      jmp ftrace_caller                                      │   │
│  │      pushq %rbp                                             │   │
│  │      ...                                                    │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  修改函数:                                                          │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  ftrace_make_nop()    - 将插桩改为 NOP                     │   │
│  │  ftrace_make_call()   - 将 NOP 改为调用指令                 │   │
│  │  ftrace_update_code() - 更新所有函数的插桩状态              │   │
│  │  ftrace_modify_code() - 修改单个函数的插桩状态              │   │
│  └─────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────┘
```

## 追踪类型

### 1. 函数追踪 (Function Trace)

```
┌─────────────────────────────────────────────────────────────────────┐
│                    Function Tracing                             │
│                                                                     │
│  原理:                                                              │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  在每个函数入口调用 ftrace_ops_list_func()                   │   │
│  │  记录:                                                      │   │
│  │  • 时间戳                                                   │   │
│  │  • 当前函数 IP                                              │   │
│  │  • 父函数 IP                                                │   │
│  │  • CPU 编号                                                 │   │
│  │  • 进程信息                                                 │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  输出示例:                                                          │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  # tracer: function                                         │   │
│  │  #                                                         │   │
│  │  #           TASK-PID    CPU#    TIMESTAMP  FUNCTION       │   │
│  │  #              | |       |         |         |             │   │
│  │    bash-1234    [001]  1234.567890  sys_open <- do_sys_open │   │
│  │    bash-1234    [001]  1234.567891  __fdget_pos <- sys_open│   │
│  │    bash-1234    [001]  1234.567892  fd_install <- sys_open │   │
│  └─────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────┘
```

### 2. 函数调用图 (Function Graph)

```
┌─────────────────────────────────────────────────────────────────────┐
│                    Function Graph Tracing                       │
│                                                                     │
│  原理:                                                              │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  1. 函数入口时: 修改返回地址为 ftrace_return_to_handler    │   │
│  │  2. 记录函数进入时间和调用栈                                │   │
│  │  3. 函数返回时: 调用 ftrace_return_to_handler              │   │
│  │  4. 记录函数退出时间和执行耗时                              │   │
│  │  5. 恢复原始返回地址并继续执行                              │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  输出示例:                                                          │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  # tracer: function_graph                                   │   │
│  │  #                                                         │   │
│  │  #           TASK-PID    CPU#    TIMESTAMP  FUNCTION       │   │
│  │  #              | |       |         |         |             │   │
│  │    bash-1234    [001]  1234.567890  + sys_open            │   │
│  │    bash-1234    [001]  1234.567891  |  + __fdget_pos      │   │
│  │    bash-1234    [001]  1234.567892  |  + fd_install       │   │
│  │    bash-1234    [001]  1234.567893  + sys_open <- 1.2us   │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  符号说明:                                                          │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  + 函数入口                                                  │   │
│  │  - 函数出口                                                  │   │
│  │  | 嵌套层级                                                  │   │
│  │  <- 执行耗时                                                 │   │
│  └─────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────┘
```

### 3. 事件追踪 (Event Tracing)

```
┌─────────────────────────────────────────────────────────────────────┐
│                    Event Tracing                               │
│                                                                     │
│  原理:                                                              │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  使用 tracepoint 机制在关键代码位置插入追踪点                │   │
│  │  支持:                                                      │   │
│  │  • 调度器事件 (sched_switch, sched_wakeup)                  │   │
│  │  • 中断事件 (irq_handler_entry, irq_handler_exit)           │   │
│  │  • 系统调用事件 (sys_enter, sys_exit)                       │   │
│  │  • 内存事件 (kmalloc, kfree)                                │   │
│  │  • 自定义事件                                               │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  tracepoint 定义:                                                   │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  DECLARE_TRACE(sched_switch,                                 │   │
│  │      TP_PROTO(struct task_struct *prev,                      │   │
│  │               struct task_struct *next),                     │   │
│  │      TP_ARGS(prev, next));                                   │   │
│  │                                                             │   │
│  │  trace_sched_switch(prev, next);  // 触发追踪点             │   │
│  └─────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────┘
```

## tracefs 接口

### 主要文件

| 文件 | 说明 |
|------|------|
| `current_tracer` | 当前使用的追踪器 |
| `available_tracers` | 可用的追踪器列表 |
| `trace` | 追踪输出 |
| `trace_pipe` | 追踪管道 (消费模式) |
| `ftrace_filter` | 函数过滤规则 |
| `ftrace_notrace` | 函数排除规则 |
| `set_ftrace_pid` | PID 过滤 |
| `function_graph` | 函数调用图选项 |
| `buffer_size_kb` | 缓冲区大小 |
| `options` | 追踪选项 |

### 使用示例

```bash
# 查看可用追踪器
cat /sys/kernel/tracing/available_tracers

# 设置追踪器为函数调用图
echo function_graph > /sys/kernel/tracing/current_tracer

# 设置函数过滤
echo "*open*" > /sys/kernel/tracing/ftrace_filter

# 设置 PID 过滤
echo $$ > /sys/kernel/tracing/set_ftrace_pid

# 开始追踪
echo 1 > /sys/kernel/tracing/tracing_on

# 执行需要追踪的操作
ls /

# 停止追踪
echo 0 > /sys/kernel/tracing/tracing_on

# 查看追踪结果
cat /sys/kernel/tracing/trace
```

## 编译配置

| 配置项 | 说明 |
|--------|------|
| CONFIG_FUNCTION_TRACER | 函数追踪 |
| CONFIG_FUNCTION_GRAPH_TRACER | 函数调用图追踪 |
| CONFIG_DYNAMIC_FTRACE | 动态 ftrace |
| CONFIG_FTRACE_SYSCALLS | 系统调用追踪 |

| CONFIG_TRACEPOINTS | tracepoint 支持 |

## 性能影响

| 方面 | 影响 |
|------|------|
| 禁用状态 | 几乎无影响 (只有 NOP 指令) |
| 启用状态 | 每个函数调用增加少量开销 |
| 函数调用图 | 开销较大 (修改返回地址) |
| 缓冲区大小 | 影响内存占用 |
| 过滤规则 | 减少追踪数据量 |

## 局限性

1. **函数插桩**：不支持内联函数的追踪
2. **性能开销**：启用时会增加函数调用开销
3. **缓冲区溢出**：缓冲区满时会丢弃旧数据
4. **符号解析**：需要 kallsyms 支持

## 总结

ftrace 是一个强大的内核追踪工具：

1. **函数追踪**：追踪函数入口/出口
2. **调用图**：可视化函数调用关系和执行时间
3. **事件追踪**：追踪系统事件
4. **动态开关**：运行时启用/禁用
5. **灵活过滤**：支持函数名、PID 等过滤

ftrace 是非侵入式的，对系统性能影响小，是内核开发和性能分析的重要工具。
