# kprobe/uprobe — 内核/用户空间探针

## 概述

kprobe 和 uprobe 是 Linux 内核提供的强大探针机制，允许开发者在运行时动态地在任意指令地址设置探测点，而无需修改源代码或重新编译内核。

- **kprobe**：内核空间探针，用于探测内核函数
- **uprobe**：用户空间探针，用于探测用户态程序

## kprobe 工作原理

### 核心数据结构

```
struct kprobe {
    struct hlist_node        hlist;          /* 哈希链表 */
    struct list_head         list;           /* 多处理器链表 */
    unsigned long            nmissed;        /* 错过的探测次数 */
    kprobe_opcode_t          *addr;          /* 探测地址 */
    const char               *symbol_name;   /* 符号名 */
    unsigned int             offset;         /* 符号内偏移 */
    kprobe_pre_handler_t     pre_handler;    /* 前置处理函数 */
    kprobe_post_handler_t    post_handler;   /* 后置处理函数 */
    kprobe_opcode_t          opcode;         /* 保存的原始指令 */
    struct arch_specific_insn ainsn;         /* 架构特定指令 */
    u32                      flags;          /* 状态标志 */
};
```

### 探针类型

| 类型 | 说明 | 回调函数 |
|------|------|----------|
| **kprobe** | 函数入口/任意位置探针 | pre_handler, post_handler |
| **jprobe** | 跳转探针，可访问函数参数 | entry |
| **kretprobe** | 函数返回探针 | handler, entry_handler |

### kprobe 工作流程

```
┌─────────────────────────────────────────────────────────────────────┐
│                    kprobe Workflow                               │
│                                                                     │
│  注册探针:                                                          │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  1. 解析符号名和偏移，获取探测地址                          │   │
│  │  2. 保存原始指令到 kprobe.opcode                           │   │
│  │  3. 将探测地址处的指令替换为断点指令                        │   │
│  │  4. 将 kprobe 添加到全局哈希表                             │   │
│  │  5. 如果探测地址在函数入口，尝试使用 ftrace 优化路径        │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                           │                                         │
│                           ▼                                         │
│  触发探针:                                                          │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  1. CPU 执行到断点指令，触发异常                            │   │
│  │  2. 异常处理程序查找 kprobe 哈希表                         │   │
│  │  3. 调用 pre_handler()                                     │   │
│  │  4. 在安全位置执行原始指令 (单步执行)                       │   │
│  │  5. 调用 post_handler()                                    │   │
│  │  6. 恢复执行流                                             │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                           │                                         │
│                           ▼                                         │
│  注销探针:                                                          │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  1. 从全局哈希表中移除 kprobe                              │   │
│  │  2. 恢复原始指令                                           │   │
│  │  3. 释放资源                                               │   │
│  └─────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────┘
```

### 指令仿真

```
┌─────────────────────────────────────────────────────────────────────┐
│                    Instruction Emulation                        │
│                                                                     │
│  问题: 原始指令被替换为断点指令，如何执行原始指令?                    │
│                                                                     │
│  方案:                                                              │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  1. 将原始指令复制到安全位置 (kprobe.opcode)                │   │
│  │  2. 使用单步执行 (step) 方式执行该指令                      │   │
│  │  3. 处理指令的副作用 (内存访问、寄存器修改等)               │   │
│  │  4. 恢复寄存器状态                                         │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  复杂指令处理:                                                       │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  • 分支指令: 计算目标地址，修改 PC                          │   │
│  │  • 内存访问指令: 在安全上下文中执行                          │   │
│  │  • 系统调用指令: 模拟执行，处理返回值                        │   │
│  │  • 不可仿真指令: 禁用探针并跳过                              │   │
│  └─────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────┘
```

### kretprobe 工作原理

```
┌─────────────────────────────────────────────────────────────────────┐
│                    kretprobe Workflow                           │
│                                                                     │
│  原理: 修改函数返回地址，使其指向 kretprobe_trampoline              │
│                                                                     │
│  注册:                                                              │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  1. 在函数入口设置 kprobe                                   │   │
│  │  2. 当函数被调用时，entry_handler 保存原始返回地址            │   │
│  │  3. 将返回地址修改为 kretprobe_trampoline                   │   │
│  │  4. 使用 objpool 管理返回实例                               │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                           │                                         │
│                           ▼                                         │
│  返回时:                                                            │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  1. 函数返回时跳转到 kretprobe_trampoline                   │   │
│  │  2. kretprobe_trampoline 调用 handler()                     │   │
│  │  3. handler() 可以获取函数返回值                             │   │
│  │  4. 恢复原始返回地址                                         │   │
│  │  5. 跳转到原始返回地址继续执行                               │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  maxactive:                                                          │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  • 同时活跃的函数调用实例最大数量                            │   │
│  │  • 如果超过此限制，返回探测将被忽略                          │   │
│  │  • nmissed 记录被忽略的次数                                 │   │
│  │  • 默认值取决于内核配置和系统内存                            │   │
│  └─────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────┘
```

## uprobe 工作原理

### 核心数据结构

```
struct uprobe {
    struct inode             *inode;         /* 目标文件 inode */
    loff_t                   offset;         /* 文件内偏移 */
    struct uprobe_consumer   *consumer;      /* 消费者列表 */
    struct mm_struct         *mm;            /* 内存映射 */
    unsigned long            vaddr;          /* 虚拟地址 */
    u8                       opcode;         /* 原始指令 */
    struct rcu_head          rcu;            /* RCU 头 */
};
```

### uprobe 与 kprobe 的区别

| 特性 | kprobe | uprobe |
|------|--------|--------|
| 目标空间 | 内核空间 | 用户空间 |
| 地址类型 | 物理地址 | 虚拟地址 |
| 页表管理 | 无需管理 | 需要管理 vma |
| 指令仿真 | 在内核中执行 | 在用户态执行 |
| 上下文切换 | 无需切换 | 需要切换到用户态 |
| 安全性 | 更高风险 | 相对安全 |

### uprobe 工作流程

```
┌─────────────────────────────────────────────────────────────────────┐
│                    uprobe Workflow                              │
│                                                                     │
│  注册:                                                              │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  1. 解析目标文件路径和偏移                                   │   │
│  │  2. 获取目标文件的 inode                                     │   │
│  │  3. 创建 uprobe 结构并保存原始指令                           │   │
│  │  4. 注册到 uprobe 全局列表                                  │   │
│  │  5. 对所有已映射该文件的进程设置断点                         │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                           │                                         │
│                           ▼                                         │
│  设置断点:                                                          │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  1. 遍历所有映射该文件的进程                                 │   │
│  │  2. 找到对应的 vma                                          │   │
│  │  3. 计算虚拟地址 (vma->vm_start + offset)                   │   │
│  │  4. 将该页设置为可写                                         │   │
│  │  5. 将指令替换为断点指令                                     │   │
│  │  6. 刷新指令缓存                                             │   │
│  │  7. 将该页恢复为只读                                         │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                           │                                         │
│                           ▼                                         │
│  触发:                                                              │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  1. 用户态程序执行到断点指令                                 │   │
│  │  2. 触发 SIGTRAP 信号                                       │   │
│  │  3. 内核捕获信号，查找 uprobe                                │   │
│  │  4. 调用 pre_handler()                                      │   │
│  │  5. 在用户态单步执行原始指令                                 │   │
│  │  6. 调用 post_handler()                                     │   │
│  │  7. 恢复执行                                                 │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                           │                                         │
│                           ▼                                         │
│  注销:                                                              │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  1. 对所有已映射该文件的进程恢复原始指令                     │   │
│  │  2. 从全局列表中移除 uprobe                                 │   │
│  │  3. 释放资源                                                 │   │
│  └─────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────┘
```

## 性能影响

| 方面 | kprobe | uprobe |
|------|--------|--------|
| 标准模式 | 每个探测点约 1-2 us | 每个探测点约 5-10 us |
| 优化模式 | 接近 ftrace 开销 | 不适用 |
| 内存占用 | 每个探针约 100 bytes | 每个探针约 200 bytes |
| 并发限制 | 无 | maxactive 限制 |

## 安全性考虑

### nokprobe_inline

```
nokprobe_inline
int my_sensitive_function(void)
{
    /* 这个函数不能被探测 */
}
```

用于标记敏感函数，防止 kprobe 探测。

### 安全检查

| 检查项 | 说明 |
|--------|------|
| 探测地址有效性 | 检查是否在内核代码段 |
| 嵌套探测 | 防止 kprobe 自身被探测 |
| 中断安全 | 确保在中断上下文中安全执行 |
| 内存安全 | 防止越界访问 |

## 使用示例

### kprobe 示例

```c
#include <linux/kprobes.h>

static struct kprobe kp = {
    .symbol_name = "sys_open",
};

static int handler_pre(struct kprobe *p, struct pt_regs *regs)
{
    pr_info("sys_open called\n");
    return 0;
}

static void handler_post(struct kprobe *p, struct pt_regs *regs, unsigned long flags)
{
    pr_info("sys_open returned\n");
}

static int __init kprobe_init(void)
{
    kp.pre_handler = handler_pre;
    kp.post_handler = handler_post;
    register_kprobe(&kp);
    pr_info("kprobe registered\n");
    return 0;
}

static void __exit kprobe_exit(void)
{
    unregister_kprobe(&kp);
    pr_info("kprobe unregistered\n");
}

module_init(kprobe_init);
module_exit(kprobe_exit);
```

### kretprobe 示例

```c
#include <linux/kprobes.h>

static struct kretprobe rp = {
    .kp.symbol_name = "sys_open",
    .handler = ret_handler,
    .maxactive = 20,
};

static int ret_handler(struct kretprobe_instance *ri, struct pt_regs *regs)
{
    pr_info("sys_open returned: %ld\n", regs_return_value(regs));
    return 0;
}

static int __init kretprobe_init(void)
{
    register_kretprobe(&rp);
    pr_info("kretprobe registered\n");
    return 0;
}

static void __exit kretprobe_exit(void)
{
    unregister_kretprobe(&rp);
    pr_info("kretprobe unregistered\n");
}

module_init(kretprobe_init);
module_exit(kretprobe_exit);
```

## 总结

kprobe/uprobe 是强大的动态探针机制：

1. **kprobe**：内核空间任意位置探测，支持函数入口/出口/中间位置
2. **uprobe**：用户空间程序探测，支持动态库和可执行文件
3. **优化路径**：使用 ftrace 减少性能开销
4. **trace_kprobe/trace_uprobe**：通过 tracefs 动态创建探针事件
5. **参数提取**：支持寄存器、栈、内存等多种参数提取方式

这些机制为内核和用户空间调试提供了极大的灵活性，是 Linux 调试工具链的重要组成部分。
