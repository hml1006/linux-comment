# kmemleak — 内存泄漏检测

## 概述

kmemleak 是 Linux 内核提供的内存泄漏检测工具，通过追踪内存分配和释放，自动检测未释放的内存块。kmemleak 使用垃圾回收算法，定期扫描内核内存，查找不再被引用的分配对象。

## 核心数据结构

### kmemleak_object

```
struct kmemleak_object {
    raw_spinlock_t           lock;           /* 对象锁 */
    unsigned int             flags;          /* 状态标志 */
    struct list_head         object_list;    /* 对象链表 */
    struct list_head         gray_list;      /* 灰色对象列表 */
    struct rb_node           rb_node;        /* 红黑树节点 */
    struct rcu_head          rcu;            /* RCU 头 */
    atomic_t                 use_count;      /* 引用计数 */
    unsigned int             del_state;      /* 删除状态 */
    unsigned long            pointer;        /* 内存块地址 */
    size_t                   size;           /* 内存块大小 */
    unsigned long            excess_ref;     /* 多余引用目标 */
    int                      min_count;      /* 最小引用计数 */
    unsigned long            trace[MAX_TRACE]; /* 分配时的调用栈 */
    unsigned int             trace_len;      /* 栈追踪长度 */
    struct kmemleak_scan_area *scan_area;   /* 扫描区域 */
    unsigned int             nr_scan_areas;  /* 扫描区域数量 */
};
```

### kmemleak_scan_area

```
struct kmemleak_scan_area {
    struct hlist_node        node;           /* 哈希链表 */
    unsigned long            start;          /* 扫描起始地址 */
    size_t                   size;           /* 扫描大小 */
};
```

```
│  │  1. 检查是否需要追踪 (SLAB_NOLEAKTRACE)                     │   │
│  │  2. 获取调用栈追踪 (stack_trace_save)                       │   │
│  │  3. 调用 create_object() 创建对象元数据                    │   │
│  │  4. 将对象添加到 object_list 和 object_tree_root           │   │

│  └─────────────────────────────────────────────────────────────┘   │
│                           │                                         │
│                           ▼                                         │
│  create_object():                                                   │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  1. 检查地址有效性 (是否在有效内存区域)                      │   │

│  │  5. 设置 use_count = 1                                     │   │
│  │  6. 添加到 object_list 和 object_tree_root                  │   │

└─────────────────────────────────────────────────────────────────────┘
```

### 对象释放流程

```
┌─────────────────────────────────────────────────────────────────────┐
│                    Object Deletion Flow                         │
│                                                                     │
│  kmemleak_free():                                                   │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  1. 从 object_tree_root 查找对象                           │   │
│  │  2. 调用 delete_object() 删除对象                          │   │

│  │  4. 设置 del_state = DELETED                              │   │
│  │  5. 递减 use_count，可能触发释放                           │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                           │                                         │
│                           ▼                                         │
│  put_object():                                                      │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  1. 递减 use_count                                         │   │
│  │  2. 如果 use_count == 0，调度 RCU 回调释放对象              │   │
│  │  3. 通过 call_rcu() 异步释放 kmemleak_object              │   │
│  └─────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────┘
```

## 垃圾回收算法

### Mark-Sweep 算法

```
┌─────────────────────────────────────────────────────────────────────┐
│                    Mark-Sweep Algorithm                         │
│                                                                     │
│  原理: 标记所有可达对象，未标记的即为泄漏                             │
│                                                                     │
│  步骤1: 初始化灰色列表 (Gray List)                                   │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  1. 将所有对象标记为白色 (未访问)                           │   │
│  │  2. 将根对象添加到灰色列表                                  │   │
│  │     • 内核数据段中的指针                                   │   │
│  │     • 栈上的指针                                           │   │
│  │     • slab 缓存中的指针                                    │   │
│  │     • 其他已知的根指针                                     │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                           │                                         │
│                           ▼                                         │
│  步骤2: 标记阶段 (Mark Phase)                                        │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  while (灰色列表不为空):                                   │   │
│  │    1. 从灰色列表中取出一个对象                             │   │
│  │    2. 扫描该对象的内存内容，查找指向其他对象的指针           │   │
│  │    3. 对于每个找到的指针:                                   │   │
│  │       a. 如果目标对象是白色，标记为灰色并添加到灰色列表     │   │
│  │       b. 如果目标对象已标记，跳过                           │   │
│  │    4. 将当前对象标记为黑色                                 │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                           │                                         │
│                           ▼                                         │
│  步骤3: 清除阶段 (Sweep Phase)                                       │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  遍历所有对象:                                             │   │
│  │    1. 如果对象仍然是白色 → 报告为内存泄漏                   │   │
│  │    2. 如果对象是黑色 → 保持不变                           │   │
│  │    3. 重置所有对象的颜色标记                               │   │
│  └─────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────┘
```

## 扫描线程

### 自动扫描机制

```
┌─────────────────────────────────────────────────────────────────────┐
│                    Scan Thread                                 │
│                                                                     │
│  scan_thread():                                                     │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  1. 初始化等待队列                                         │   │
│  │  2. 首次扫描延迟: SECS_FIRST_SCAN (60 秒)                  │   │
│  │  3. 循环:                                                  │   │
│  │     a. 等待 SECS_SCAN_WAIT (600 秒)                       │   │
│  │     b. 检查是否需要扫描                                   │   │
│  │     c. 获取 scan_mutex                                    │   │
│  │     d. 调用 kmemleak_scan() 执行扫描                      │   │
│  │     e. 释放 scan_mutex                                    │   │
│  │  4. 直到 kmemleak 被关闭或系统关机                        │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  手动触发:                                                           │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  echo scan > /sys/kernel/debug/kmemleak                    │   │
│  └─────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────┘
```

### 使用方式

```bash
# 查看泄漏报告
cat /sys/kernel/debug/kmemleak

# 立即触发扫描
echo scan > /sys/kernel/debug/kmemleak

# 清除泄漏报告
echo clear > /sys/kernel/debug/kmemleak

# 关闭 kmemleak
echo off > /sys/kernel/debug/kmemleak

# 设置栈追踪深度
echo stack=30 > /sys/kernel/debug/kmemleak

# 设置扫描间隔 (秒)
echo scan_sleep=300 > /sys/kernel/debug/kmemleak

# 标记对象为非泄漏
echo notleak <address> > /sys/kernel/debug/kmemleak

# 忽略对象
echo ignore <address> > /sys/kernel/debug/kmemleak
```

## API 接口

### 追踪控制


### 泄漏标记

```c
void kmemleak_not_leak(const void *ptr);        /* 标记为非泄漏 */
void kmemleak_transient_leak(const void *ptr);   /* 标记为临时泄漏 */
```


## 总结

kmemleak 是一个强大的内存泄漏检测工具：

1. **自动追踪**：追踪所有内核内存分配
2. **垃圾回收**：使用 Mark-Sweep 算法检测泄漏
3. **定期扫描**：自动或手动触发扫描
4. **详细报告**：提供泄漏对象的调用栈和大小
5. **灵活控制**：支持标记非泄漏对象、调整扫描参数

kmemleak 对系统性能有一定影响，但可以通过调整参数平衡检测精度和性能开销。
