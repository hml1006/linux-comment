# KGDB — GDB 远程调试

## 概述

KGDB (Kernel GDB) 是一个允许通过 GDB 远程调试 Linux 内核的机制。它实现了 GDB 远程协议，使得开发者可以使用熟悉的 GDB 工具进行内核源码级调试。

## GDB 远程协议

### 协议格式

```
$<data>#<checksum>
```

- `$` - 数据包开始标志
- `<data>` - 数据内容
- `#` - 分隔符
- `<checksum>` - 两个十六进制字符的校验和

### 核心命令

| 命令 | 功能 | 说明 |
|------|------|------|
| `g` | 读取寄存器 | 返回所有寄存器的值 |
| `G` | 写入寄存器 | 设置所有寄存器的值 |
| `p` | 读取内存 | 按地址读取内存 |
| `P` | 写入内存 | 按地址写入内存 |
| `b` | 设置断点 | 设置软件断点 |
| `B` | 设置硬件断点 | 设置硬件断点 |
| `z` | 删除断点 | 删除断点 |
| `c` | 继续执行 | 继续执行程序 |
| `s` | 单步执行 | 执行一条指令 |
| `n` | 下一行 | 执行到下一行 |
| `k` | 终止连接 | 断开调试连接 |
| `?` | 查询状态 | 查询当前状态 |

### 数据包处理流程

```
┌─────────────────────────────────────────────────────────────────────┐
│                    GDB Packet Processing                         │
│                                                                     │
│  get_packet():                                                      │
│  ┌─────────────────────────────────────────────────────┐   │       │
│  │  1. 等待 '$' 字符 (数据包开始)                       │   │       │
│  │  2. 读取数据直到 '#' 字符                           │   │       │
│  │  3. 计算校验和                                       │   │       │
│  │  4. 验证校验和是否匹配                               │   │       │
│  │  5. 如果校验失败，发送 'N' 表示重试                   │   │       │
│  │  6. 如果校验成功，发送 '+' 表示确认                   │   │       │
│  └─────────────────────────────────────────────────────┘   │       │
│                           │                                         │
│                           ▼                                         │
│  gdb_serial_stub():                                                 │
│  ┌─────────────────────────────────────────────────────┐   │       │
│  │  1. 解析命令字符                                     │   │       │
│  │  2. 根据命令调用相应处理函数                          │   │       │
│  │  3. 构建响应数据包                                   │   │       │
│  │  4. 调用 put_packet() 发送响应                       │   │       │
│  │  5. 等待下一个命令                                   │   │       │
│  └─────────────────────────────────────────────────────┘   │       │
│                           │                                         │
│                           ▼                                         │
│  put_packet():                                                      │
│  ┌─────────────────────────────────────────────────────┐   │       │
│  │  1. 计算数据校验和                                   │   │       │
│  │  2. 格式化数据包 ($<data>#<checksum>)               │   │       │
│  │  3. 发送数据包                                       │   │       │
│  │  4. 等待确认 ('+' 或 '-')                           │   │       │
│  │  5. 如果收到 '-', 重新发送                           │   │       │
│  └─────────────────────────────────────────────────────┘   │       │
└─────────────────────────────────────────────────────────────────────┘
```

## 核心数据结构

### kgdb_state

```
struct kgdb_state {
    int                     ex_vector;      /* 异常向量 */
    int                     signo;          /* 信号号 */
    int                     err_code;       /* 错误码 */
    int                     cpu;            /* 当前 CPU */
    int                     pass_exception; /* 异常传递标志 */
    unsigned long           thr_query;      /* 线程查询号 */
    unsigned long           threadid;       /* 线程 ID */
    long                    kgdb_usethreadid; /* 使用线程 ID */
    struct pt_regs          *linux_regs;    /* Linux 寄存器 */
    atomic_t                *send_ready;    /* 发送就绪标志 */
};
```

该结构保存 KGDB 的状态信息，用于协议处理。

### debuggerinfo_struct

```
struct debuggerinfo_struct {
    void                    *debuggerinfo;  /* 调试器信息 */
    struct task_struct      *task;          /* 当前任务 */
    int                     exception_state;/* 异常状态 */
    int                     ret_state;      /* 返回状态 */
    int                     irq_depth;      /* IRQ 深度 */
    int                     enter_kgdb;     /* 进入 KGDB 标志 */
    bool                    rounding_up;    /* 正在收集 CPU */
};
```

保存每个 CPU 的调试状态，支持多 CPU 调试。

### kgdb_io

```
struct kgdb_io {
    const char              *name;          /* IO 模块名称 */
    int                     (*read_char)(void);
    void                    (*write_char)(u8);
    int                     (*read_buffer)(char *, int);
    int                     (*write_buffer)(const char *, int);
    void                    (*pre_exception)(void);
    void                    (*post_exception)(void);
    struct list_head        list;
};
```

定义 IO 接口，支持多种传输方式。

## 异常处理流程

```
┌─────────────────────────────────────────────────────────────────────┐
│                    KGDB Exception Handling                        │
│                                                                     │
│  异常触发:                                                          │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  1. 断点指令 (brk) 触发同步异常                            │   │
│  │  2. 其他异常 (缺页、非法指令等)                            │   │
│  │  3. 远程 GDB 发送 break 命令                              │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                           │                                         │
│                           ▼                                         │
│  kgdb_handle_exception():                                           │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  1. 检查递归异常 (exception_level)                        │   │
│  │  2. 保存寄存器状态到 debuggerinfo_struct                   │   │
│  │  3. 处理多 CPU 协调                                       │   │
│  │  4. 选择调试模式 (KDB vs KGDB)                            │   │

│  └─────────────────────────────────────────────────────────────┘   │

│                           ▼                                         │

│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  1. 检查是否有远程 GDB 连接                                │   │
│  │  2. 如果没有连接，检查是否进入 KDB                         │   │
│  │  3. 如果有连接，调用 gdb_serial_stub()                     │   │
│  │  4. 处理异常传递                                           │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                           │                                         │
│                           ▼                                         │
│  gdb_serial_stub():                                                 │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  1. 初始化寄存器缓冲区                                     │   │
│  │  2. 发送停止信号通知 GDB                                  │   │
│  │  3. 进入命令循环                                          │   │
│  │  4. 接收并处理 GDB 命令                                   │   │
│  │  5. 直到收到继续或退出命令                                 │   │
```

## 多 CPU 调试

### CPU 协调机制

```
┌─────────────────────────────────────────────────────────────────────┐
│                    Multi-CPU Debugging                          │
│                                                                     │
│  exception_state 标志:                                              │
│  • DCPU_WANT_MASTER (0x1) - 等待成为主调试 CPU                    │
│  • DCPU_NEXT_MASTER (0x2) - 主 CPU 切换                          │
│  • DCPU_IS_SLAVE (0x4) - 从 CPU 进入异常                        │
│  • DCPU_WANT_BT (0x8) - 从 CPU 执行堆栈追踪后清除标志            │
│                                                                     │
│  协调流程:                                                          │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  CPU 0 (Master):                                           │   │
│  │    │                                                       │   │
│  │    ├── 触发断点 → kgdb_handle_exception()                  │   │
│  │    ├── 设置 DCPU_WANT_MASTER                               │   │
│  │    ├── 发送 IPI 到其他 CPU                                 │   │
│  │    └── 等待其他 CPU 进入异常                               │   │
│  │                                                             │   │
│  │  CPU 1-N (Slave):                                          │   │
│  │    │                                                       │   │
│  │    ├── 收到 IPI → 进入异常                                 │   │
│  │    ├── 设置 DCPU_IS_SLAVE                                  │   │
│  │    └── 等待 Master 指令                                    │   │
│  │                                                             │   │
│  │  同步完成后:                                                 │   │
│  │    • Master CPU 处理 GDB 命令                              │   │
│  │    • Slave CPU 保持暂停状态                                │   │
│  │    • 可以切换到任意 CPU 查看状态                            │   │
│  └─────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────┘
```

## 断点管理

### 断点类型

| 类型 | 说明 | 限制 |
|------|------|------|
| 软件断点 | 替换指令为断点指令 | 无数量限制 |
| 硬件断点 | 使用 CPU 调试寄存器 | 受硬件限制（通常2-4个） |

### 断点操作

```
┌─────────────────────────────────────────────────────────────────────┐
│                    Breakpoint Operations                        │
│                                                                     │
│  设置软件断点 (dbg_set_sw_break):                                   │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  1. 检查地址是否已存在断点                                  │   │
│  │  2. 保存原始指令到断点列表                                  │   │
│  │  3. 替换为断点指令 (ARM: brk #0xf000)                      │   │
│  │  4. 刷新指令缓存                                            │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  删除软件断点 (dbg_remove_sw_break):                                │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  1. 查找断点列表中的地址                                    │   │
│  │  2. 恢复原始指令                                            │   │
│  │  3. 刷新指令缓存                                            │   │
│  │  4. 从列表中删除                                            │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  断点激活/停用 (dbg_activate_sw_breakpoints):                        │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  • 在异常处理前停用所有断点                                │   │
│  │  • 在异常处理后重新激活所有断点                            │   │
│  │  • 防止递归断点触发                                        │   │
│  └─────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────┘
```

## 使用流程

### 1. 内核配置

```bash
# 编译内核时启用以下选项
CONFIG_KGDB=y
CONFIG_KGDB_SERIAL_CONSOLE=y
CONFIG_KGDB_KDB=y

# 内核参数
kgdboc=ttyS0,115200 kgdbwait
```

### 2. 连接 GDB

```bash
# 使用交叉编译器
$ aarch64-linux-gnu-gdb vmlinux

# 设置串口
(gdb) target remote /dev/ttyUSB0

# 或者使用以太网
(gdb) target remote 10.0.0.2:1234

# 加载符号
(gdb) symbol-file vmlinux

# 设置断点
(gdb) break start_kernel

# 继续执行
(gdb) continue
```

### 3. 调试操作

```bash
# 查看堆栈
(gdb) bt

# 查看寄存器
(gdb) info registers

# 查看内存
(gdb) x/10x 0xffffff80081d2400

# 查看变量
(gdb) print current->comm

# 条件断点
(gdb) break do_fork if nr_threads > 100

# 单步执行
(gdb) step

# 下一行
(gdb) next

# 继续执行
(gdb) continue

# 退出调试
(gdb) detach
```

## 与 KDB 的切换

```
┌─────────────────────────────────────────────────────────────────────┐
│                   KDB <-> KGDB Switching                        │
│                                                                     │
│  KDB -> KGDB:                                                       │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  kdb> g                                                    │   │
│  │  → 切换到 KGDB 模式，等待远程 GDB 连接                     │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  KGDB -> KDB:                                                       │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  (gdb) monitor k                                           │   │
│  │  → 切换到 KDB 模式，本地命令行交互                         │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
│  自动切换:                                                          │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  • 如果有远程 GDB 连接，自动进入 KGDB                       │   │
│  │  • 如果没有远程连接，进入 KDB                               │   │
│  │  • 可通过 kgdb_kdb_mode 变量控制默认模式                    │   │
│  └─────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────┘
```

## 性能影响

| 方面 | 影响 |
|------|------|
| 启动时间 | 启用 kgdbwait 会在启动时等待连接 |
| 运行性能 | 调试器未激活时影响很小 |
| 断点命中 | 会暂停所有 CPU |
| 内存占用 | 约几 KB |

## 局限性

1. **实时性**：断点会暂停所有 CPU，影响实时任务
2. **多线程**：切换线程时需要重新同步
3. **硬件断点**：数量受 CPU 硬件限制
4. **信号处理**：某些信号可能无法正确处理

## 总结

KGDB 提供了强大的远程调试能力：

1. **源码级调试**：可以使用 GDB 的所有功能
2. **条件断点**：支持复杂的断点条件
3. **变量检查**：可以查看和修改内核变量
4. **多 CPU 调试**：支持 SMP 系统的调试
5. **与 KDB 集成**：可以在两种模式间切换

KGDB 是内核开发中不可或缺的调试工具，特别适合复杂问题的定位和分析。
