# 5.GIC

Generic Interrupt Controller CPU interface
**GICv4架构支持**：

* 两种安全状态
* 中断虚拟化
* SGI中断
* Message Based中断
* 通过CPU interface访问系统寄存器
* 中断掩码和优先级
* 支持cluster， 包含超过8个core
* 支持电源管理环境唤醒时间
  **GIC中断分组功能**
* 配置每个中断属于某个中断group
* 使用IRQ或者FIQ方式把Group1中断信号发送到目标core
* 只能使用FIQ方式把Group0中断信号发送到目标core
* 用统一方案处理Group0和Group1中断优先级

## 硬件中断类型

SGI (Software Generated Interrupt)：软件触发的中断。软件可以通过写 GICD_SGIR 寄存器来触发一个中断事件，一般用于核间通信，内核中的 IPI：inter-processor interrupts 就是基于 SGI。

PPI (Private Peripheral Interrupt)：私有外设中断。这是每个核心私有的中断。PPI会送达到指定的CPU上，应用场景有CPU本地时钟。

SPI (Shared Peripheral Interrupt)：公用的外部设备中断，也定义为共享中断。中断产生后，可以分发到某一个CPU上。比如按键触发一个中断，手机触摸屏触发的中断。

LPI (Locality-specific Peripheral Interrupt)：LPI 是 GICv3 中的新特性，它们在很多方面与其他类型的中断不同。LPI 始终是基于消息的中断，它们的配置保存在表中而不是寄存器。比如 PCIe 的 MSI/MSI-x 中断

## 内核 GICv3 驱动总览

前面几节描述的是 GIC 的架构视图。Linux 侧的实现集中在 `drivers/irqchip/irq-gic-v3.c`（GICD/GICR/CPU interface）与 `drivers/irqchip/irq-gic-v3-its.c`（ITS/LPI/MSI），两者通过 IRQ domain 层级串起来。

本树 `.config` 中 `CONFIG_ARM_GIC_V3=y`、`CONFIG_ARM_GIC_V3_ITS=y`、`CONFIG_ARM_GIC_V2M=y`、`CONFIG_ARM_GIC_V5=y`，但 `CONFIG_ARM64_PSEUDO_NMI` **未启用**——这意味着 GIC 的优先级掩码机制虽然代码完整，实际却不会把任何 IRQ 提升为伪 NMI。下文涉及伪 NMI 的部分均属"源码存在，当前配置未启用"。

驱动的职责可以拆成四块：

| 职责 | 关键函数 | 对应硬件 |
| :-- | :-- | :-- |
| 全局初始化 | `gic_of_init` → `gic_init_bases` → `gic_dist_init` | Distributor |
| 每 CPU 初始化 | `gic_cpu_init` → `gic_populate_rdist` + `gic_cpu_sys_reg_init` | Redistributor + CPU interface |
| 中断分发 | `gic_handle_irq` → `generic_handle_domain_irq` | CPU interface IAR/EOIR |
| MSI/LPI | `its_init` → `its_irq_domain_alloc` → ITS 命令 | ITS |

## 核心数据结构

### gic_chip_data

全局单例 `gic_data`（`drivers/irqchip/irq-gic-v3.c:83`）的类型定义在 `drivers/irqchip/irq-gic-v3.c:56`：

```c
struct redist_region {
	void __iomem		*redist_base;
	phys_addr_t		phys_base;
	bool			single_redist;
};

struct gic_chip_data {
	struct fwnode_handle	*fwnode;
	phys_addr_t		dist_phys_base;
	void __iomem		*dist_base;
	struct redist_region	*redist_regions;
	struct rdists		rdists;
	struct irq_domain	*domain;
	u64			redist_stride;
	u32			nr_redist_regions;
	u64			flags;
	bool			has_rss;
	unsigned int		ppi_nr;
	struct partition_affinity *parts;
	unsigned int		nr_parts;
};
```

几个字段的含义：

- `redist_regions` 是**一段连续 MMIO 区域**的数组，不是"每 CPU 一个"。一个 region 里可能包含多个 redistributor，靠 `redist_stride` 步进；DT 属性 `#redistributor-regions` 决定数组长度。
- `rdists` 才是 per-CPU 视图，见下。
- `domain` 是 GIC 的根 IRQ domain，所有 SPI/PPI/SGI/LPI 的 hwirq→virq 映射都从这里出发。
- `has_rss` 表示是否支持 Range Selector，用于向 affinity 编号大于 15 的 CPU 发 SGI。
- `parts`/`nr_parts` 对应 DT 里的 PPI 分区（`ppi-partitions`），用于把某些 PPI 绑定到特定 CPU 子集。

中断数量由 GICD_TYPER 推导（`drivers/irqchip/irq-gic-v3.c:86`）：

```c
#define GIC_ID_NR	(1U << GICD_TYPER_ID_BITS(gic_data.rdists.gicd_typer))
#define GIC_LINE_NR	min(GICD_TYPER_SPIS(gic_data.rdists.gicd_typer), 1020U)
#define GIC_ESPI_NR	GICD_TYPER_ESPIS(gic_data.rdists.gicd_typer)
```

注意 `GIC_LINE_NR` 被钳到 1020——这是传统 SPI 的上限，扩展 SPI（ESPI，4096 起）单独走 `GIC_ESPI_NR` 路径。

### rdists 与 per-CPU redistributor

`struct rdists` 定义在 `include/linux/irqchip/arm-gic-v3.h:615`：

```c
struct rdists {
	struct {
		raw_spinlock_t	rd_lock;
		void __iomem	*rd_base;
		struct page	*pend_page;
		phys_addr_t	phys_base;
		u64             flags;
		cpumask_t	*vpe_table_mask;
		void		*vpe_l1_base;
	} __percpu		*rdist;
	phys_addr_t		prop_table_pa;
	void			*prop_table_va;
	u64			flags;
	u32			gicd_typer;
	u32			gicd_typer2;
	int                     cpuhp_memreserve_state;
	bool			has_vlpis;
	bool			has_rvpeid;
	bool			has_direct_lpi;
	bool			has_vpend_valid_dirty;
};
```

`rdist` 是 per-CPU 指针，每个 CPU 上线时填入自己那个 redistributor 的基址。`pend_page` 是该 CPU 的 LPI pending table（一页内存，每位对应一个 LPI）。`prop_table_pa/va` 是**全局共享**的 LPI property table，描述每个 LPI 的优先级与使能位——这正是前文"LPI 的配置保存在表中而不是寄存器"的落地。

`has_vlpis`/`has_rvpeid`/`has_direct_lpi` 是 GICv4 虚拟化能力标志，在 `gic_init_bases()` 里先乐观置 true，再由 quirks 或 ITS 探测结果回退。

## 初始化流程

### DT 探测：gic_of_init

入口由 `IRQCHIP_DECLARE` 注册（`drivers/irqchip/irq-gic-v3.c:2271`）：

```c
IRQCHIP_DECLARE(gic_v3, "arm,gic-v3", gic_of_init);
```

`gic_of_init()`（`drivers/irqchip/irq-gic-v3.c:2202`）从设备树取寄存器窗口：

```c
	dist_base = gic_of_iomap(node, 0, "GICD", &res);
	...
	dist_phys_base = res.start;

	err = gic_validate_dist_version(dist_base);
	...
	if (of_property_read_u32(node, "#redistributor-regions", &nr_redist_regions))
		nr_redist_regions = 1;

	rdist_regs = kzalloc_objs(*rdist_regs, nr_redist_regions);
	...
	for (i = 0; i < nr_redist_regions; i++) {
		rdist_regs[i].redist_base = gic_of_iomap(node, 1 + i, "GICR", &res);
		...
		rdist_regs[i].phys_base = res.start;
	}

	if (of_property_read_u64(node, "redistributor-stride", &redist_stride))
		redist_stride = 0;

	gic_enable_of_quirks(node, gic_quirks, &gic_data);

	err = gic_init_bases(dist_phys_base, dist_base, rdist_regs,
			     nr_redist_regions, redist_stride, &node->fwnode);
```

`gic_validate_dist_version()` 读 GICD_PIDR2 的架构版本字段，确认是 v3/v4 而不是 v2。quirks 表处理各种勘误：Cavium ThunderX1 读 GICD_TYPER2 会炸（`FLAGS_WORKAROUND_CAVIUM_ERRATUM_38539`）、HiSilicon hip06/07 的 ITS 行为异常、NVIDIA T241 的多芯片 alias 等。

### gic_init_bases

`drivers/irqchip/irq-gic-v3.c:1977` 是真正的初始化主干：

```c
	if (!is_hyp_mode_available())
		static_branch_disable(&supports_deactivate_key);

	if (static_branch_likely(&supports_deactivate_key))
		pr_info("GIC: Using split EOI/Deactivate mode\n");
	...
	typer = readl_relaxed(gic_data.dist_base + GICD_TYPER);
	gic_data.rdists.gicd_typer = typer;

	gic_enable_quirks(readl_relaxed(gic_data.dist_base + GICD_IIDR),
			  gic_quirks, &gic_data);
	...
	gic_data.domain = irq_domain_create_tree(handle, &gic_irq_domain_ops,
						 &gic_data);
	gic_data.rdists.rdist = alloc_percpu(typeof(*gic_data.rdists.rdist));
	...
	irq_domain_update_bus_token(gic_data.domain, DOMAIN_BUS_WIRED);
	...
	set_handle_irq(gic_handle_irq);

	gic_update_rdist_properties();

	gic_cpu_sys_reg_enable();
	gic_prio_init();
	gic_dist_init();
	gic_cpu_init();
	gic_enable_nmi_support();
	gic_smp_init();
	gic_cpu_pm_init();

	if (gic_dist_supports_lpis()) {
		its_init(handle, &gic_data.rdists, gic_data.domain, dist_prio_irq);
		its_cpu_init();
		its_lpi_memreserve_init();
	} else {
		if (IS_ENABLED(CONFIG_ARM_GIC_V2M))
			gicv2m_init(handle, gic_data.domain);
	}
```

顺序很讲究：

1. **先决定 EOI 模式**。`supports_deactivate_key` 默认 true，但若内核没跑在 EL2（`is_hyp_mode_available()` 为假）就关掉。split EOI/deactivate 需要 EL2 来配合 KVM 的中断转发。
2. **建 domain 再设 handler**。`set_handle_irq(gic_handle_irq)` 把 GIC 的分发函数挂到 arm64 的 `handle_arch_irq`，此后 `el1h_64_irq_handler` 才会调进来。
3. **先 distributor 后 CPU interface**。GICD 必须先使能 ARE（Affinity Routing Enable），GICR 才能正确路由。
4. **最后才碰 ITS**。LPI 依赖 redistributor 已就绪。若 GICD 不支持 LPI，退回 GICv2m（MMIO 写触发 SPI 的伪 MSI）。

`DOMAIN_BUS_WIRED` 这个 bus token 很关键：它让后续的 MSI domain 在 `irq_domain_select` 时能区分"有线中断"与"消息中断"，避免把 MSI 请求误配到 GIC 根 domain。

### Distributor 初始化：gic_dist_init

`drivers/irqchip/irq-gic-v3.c:923`：

```c
	/* Disable the distributor */
	writel_relaxed(0, base + GICD_CTLR);
	gic_dist_wait_for_rwp();

	/* Configure SPIs as non-secure Group-1. */
	for (i = 32; i < GIC_LINE_NR; i += 32)
		writel_relaxed(~0, base + GICD_IGROUPR + i / 8);

	/* Extended SPI range */
	for (i = 0; i < GIC_ESPI_NR; i += 32) {
		writel_relaxed(~0U, base + GICD_ICENABLERnE + i / 8);
		writel_relaxed(~0U, base + GICD_ICACTIVERnE + i / 8);
	}
	...
	gic_dist_config(base, GIC_LINE_NR, dist_prio_irq);

	val = GICD_CTLR_ARE_NS | GICD_CTLR_ENABLE_G1A | GICD_CTLR_ENABLE_G1;
	if (gic_data.rdists.gicd_typer2 & GICD_TYPER2_nASSGIcap) {
		pr_info("Enabling SGIs without active state\n");
		val |= GICD_CTLR_nASSGIreq;
	}

	writel_relaxed(val, base + GICD_CTLR);
	gic_dist_wait_for_rwp();

	/* Set all global interrupts to the boot CPU only. */
	affinity = gic_cpu_to_affinity(smp_processor_id());
	for (i = 32; i < GIC_LINE_NR; i++)
		gic_write_irouter(affinity, base + GICD_IROUTER + i * 8);
```

要点：

- **先关后配**。GICD_CTLR 写 0 后必须 `gic_dist_wait_for_rwp()` 等 RWP（Register Write Pending）位清零，否则后续写入可能丢失。这是 GICv3 相对 v2 的重要变化：寄存器写入是异步的。
- **全部 SPI 设为 non-secure Group-1**。Linux 假定自己跑在非安全世界，Group-0 留给安全固件（对应前文"只能使用 FIQ 方式把 Group0 中断信号发送到目标 core"）。
- **GICv3 用 IROUTER 取代 v2 的 ITARGETSR**。每个 SPI 一个 64 位 affinity 寄存器，而不是 8 位 CPU 位图——这就是架构上"支持超过 8 个 core"的实现方式。初始全部指向 boot CPU，后续由 `gic_set_affinity()` 迁移。
- `nASSGIreq` 是 GICv4.1 的"无 active 状态 SGI"特性，省掉 SGI 的 deactivate 步骤。

### Redistributor 发现：gic_populate_rdist

每个 CPU 必须找到属于自己的那个 redistributor。`__gic_populate_rdist()`（`drivers/irqchip/irq-gic-v3.c:1023`）靠 affinity 匹配：

```c
	mpidr = gic_cpu_to_affinity(smp_processor_id());

	aff = (MPIDR_AFFINITY_LEVEL(mpidr, 3) << 24 |
	       MPIDR_AFFINITY_LEVEL(mpidr, 2) << 16 |
	       MPIDR_AFFINITY_LEVEL(mpidr, 1) << 8 |
	       MPIDR_AFFINITY_LEVEL(mpidr, 0));

	typer = gic_read_typer(ptr + GICR_TYPER);
	if ((typer >> 32) == aff) {
		u64 offset = ptr - region->redist_base;
		raw_spin_lock_init(&gic_data_rdist()->rd_lock);
		gic_data_rdist_rd_base() = ptr;
		gic_data_rdist()->phys_base = region->phys_base + offset;

		pr_info("CPU%d: found redistributor %lx region %d:%pa\n", ...);
		return 0;
	}

	/* Try next one */
	return 1;
```

GICR_TYPER 的高 32 位编码了该 redistributor 对应的 CPU affinity。`gic_iterate_rdists()` 按 stride 遍历所有 region 的所有 slot，直到匹配。找不到就 `WARN` 并返回 -ENODEV，该 CPU 会被拒绝上线（`gic_check_rdist()` 检查 `broken_rdists` 掩码）。

### CPU interface 初始化

`gic_cpu_init()`（`drivers/irqchip/irq-gic-v3.c:1274`）：

```c
	/* Register ourselves with the rest of the world */
	if (gic_populate_rdist())
		return;

	gic_enable_redist(true);
	...
	rbase = gic_data_rdist_sgi_base();

	/* Configure SGIs/PPIs as non-secure Group-1 */
	for (i = 0; i < gic_data.ppi_nr + SGI_NR; i += 32)
		writel_relaxed(~0, rbase + GICR_IGROUPR0 + i / 8);

	gic_cpu_config(rbase, gic_data.ppi_nr + SGI_NR, dist_prio_irq);
	gic_redist_wait_for_rwp();

	/* initialise system registers */
	gic_cpu_sys_reg_init();
```

注意 `gic_data_rdist_sgi_base()`——GICv3 的 redistributor 有两个帧：RD_base（控制 LPI）与 SGI_base（控制 SGI/PPI，偏移 64K）。SGI/PPI 的 IGROUPR/ICENABLER 等寄存器在 SGI 帧里。

`gic_cpu_sys_reg_init()`（`drivers/irqchip/irq-gic-v3.c:1153`）配置系统寄存器侧的 CPU interface：

```c
	pribits = gic_get_pribits();
	group0 = gic_has_group0();

	/* Set priority mask register */
	if (!gic_prio_masking_enabled()) {
		write_gicreg(DEFAULT_PMR_VALUE, ICC_PMR_EL1);
	} else if (gic_supports_nmi()) {
		WARN_ON(group0 != cpus_have_group0);
		WARN_ON(gic_dist_security_disabled() != cpus_have_security_disabled);
	}

	gic_write_bpr1(0);

	if (static_branch_likely(&supports_deactivate_key)) {
		/* EOI drops priority only (mode 1) */
		gic_write_ctlr(ICC_CTLR_EL1_EOImode_drop);
	} else {
		/* EOI deactivates interrupt too (mode 0) */
		gic_write_ctlr(ICC_CTLR_EL1_EOImode_drop_dir);
	}

	/* Always whack Group0 before Group1 */
	if (group0) { ...清 ICC_AP0R*... }
	...清 ICC_AP1R*...
	isb();

	/* ... and let's hit the road... */
	gic_write_grpen1(1);
```

- `ICC_PMR_EL1` 默认 `0xf0`（`DEFAULT_PMR_VALUE`，`drivers/irqchip/irq-gic-v3.c:243`），即允许优先级数值 < 0xf0 的中断通过。
- `ICC_BPR1_EL1` 写 0 恢复复位值——注释提到某些固件会把它改得过大，导致抢占式中断完全失效。
- **APR（Active Priority Register）必须清零**。固件可能遗留 active 状态，不清会导致优先级降不下来。按 pribits 决定清几个 APR 寄存器，用 fallthrough 级联。
- `ICC_IGRPEN1_EL1` 写 1 是最后一步，真正打开 Group-1 中断投递。

CPU 热插拔时由 `gic_starting_cpu()`（`drivers/irqchip/irq-gic-v3.c:1320`）重跑这套流程：

```c

{
	gic_cpu_sys_reg_enable();
	gic_cpu_init();

	if (gic_dist_supports_lpis())
		its_cpu_init();

	return 0;
}
```

### 优先级与伪 NMI

GICv3 的优先级掩码可以模拟 NMI：把某个 IRQ 的优先级设得比 PMR 的"普通中断阈值"更高，于是 `local_irq_disable()`（改 PMR）挡不住它，只有 `daifclr` 才能挡。相关代码：

- `gic_prio_init()`（`drivers/irqchip/irq-gic-v3.c:168`）计算 `dist_prio_irq` 与 NMI 优先级。
- `gic_enable_nmi_support()`（`drivers/irqchip/irq-gic-v3.c:1961`）在 `gic_prio_masking_enabled() && !nmi_support_forbidden` 时打开 `supports_pseudo_nmis` static key。
- `gic_irq_nmi_setup()`（`drivers/irqchip/irq-gic-v3.c:597`）把单个 IRQ 提升为 NMI 优先级。

**本树 `CONFIG_ARM64_PSEUDO_NMI` 未启用**，`gic_prio_masking_enabled()` 恒假，因此 PMR 固定为 `DEFAULT_PMR_VALUE`，所有中断都走普通 IRQ 路径，`__gic_handle_irq_from_irqsoff()` 永远不会被调用。源码存在，当前配置未启用。

## 中断处理路径

### gic_handle_irq

正常路径 `__gic_handle_irq_from_irqson()`（`drivers/irqchip/irq-gic-v3.c:855`）：


读 `ICC_IAR1_EL1` 取得 INTID 并自动 acknowledge（优先级升到 running priority）。然后按 RPR 判断是不是 NMI。普通 IRQ 最终走 `__gic_handle_irq()`（`drivers/irqchip/irq-gic-v3.c:818`）：

```c
static void __gic_handle_irq(u32 irqnr, struct pt_regs *regs)
{
	if (gic_irqnr_is_special(irqnr))
		return;

	gic_complete_ack(irqnr);

	if (generic_handle_domain_irq(gic_data.domain, irqnr)) {
		WARN_ONCE(true, "Unexpected interrupt (irqnr %u)\n", irqnr);
		gic_deactivate_unhandled(irqnr);
	}
}
```

`gic_irqnr_is_special()` 过滤 1020-1023 这些特殊 INTID（spurious、Group-0 转发等）。`generic_handle_domain_irq()` 是 genirq 层的入口，查 domain 得到 virq 后调用对应的 flow handler。找不到映射就 `gic_deactivate_unhandled()` 把中断 deactivate 掉，避免它永远卡在 active 状态。

### irq_chip：EOI mode 0 与 mode 1

驱动注册了两个 `irq_chip`（`drivers/irqchip/irq-gic-v3.c:1510` 与 `:1528`）：

```c
static struct irq_chip gic_chip = {
	.name			= "GICv3",
	.irq_mask		= gic_mask_irq,
	.irq_unmask		= gic_unmask_irq,
	.irq_eoi		= gic_eoi_irq,
	.irq_set_type		= gic_set_type,
	.irq_set_affinity	= gic_set_affinity,
	...
	.ipi_send_mask		= gic_ipi_send_mask,

				  IRQCHIP_SKIP_SET_WAKE |
				  IRQCHIP_MASK_ON_SUSPEND,
};

static struct irq_chip gic_eoimode1_chip = {
	.name			= "GICv3",
	.irq_mask		= gic_eoimode1_mask_irq,
	.irq_eoi		= gic_eoimode1_eoi_irq,
	...
	.irq_set_vcpu_affinity	= gic_irq_set_vcpu_affinity,
	...

```

区别在于 EOI 语义：

| 模式 | ICC_CTLR_EL1.EOImode | EOI 效果 | mask 实现 | 使用场景 |
| :-- | :-- | :-- | :-- | :-- |
| mode 0 | drop_dir | 降优先级 + deactivate | 写 GICD_ICENABLER | 无 EL2 |
| mode 1 | drop | 只降优先级 | 写 GICD_ICENABLER + 记 active 状态 | 有 EL2，支持 KVM 转发 |

mode 1 下 deactivate 被拆出来单独做（`ICC_DIR_EL1`），这样 KVM 可以把 guest 中断的 deactivate 推迟到 guest 真正 EOI 时。`gic_eoimode1_mask_irq()` 需要额外处理"mask 时中断仍 active"的情况。

`gic_irq_domain_map()` 按 static key 选择用哪个 chip。

### 调用链

```
硬件 IRQ 信号
  → vectors: kernel_ventry 1, h, 64, irq
  → el1h_64_irq → el1h_64_irq_handler()      [entry-common.c]
  → el1_interrupt() → do_interrupt_handler()
  → handle_arch_irq = gic_handle_irq          [irq-gic-v3.c]
  → __gic_handle_irq_from_irqson()
      gic_read_iar()                          // ICC_IAR1_EL1
  → __gic_handle_irq()
  → generic_handle_domain_irq(gic_data.domain, irqnr)
  → irq_desc->handle_irq = handle_fasteoi_irq / handle_percpu_devid_irq
  → action->handler()                         // 驱动 ISR
  → chip->irq_eoi = gic_eoi_irq / gic_eoimode1_eoi_irq
      写 ICC_EOIR1_EL1（+ ICC_DIR_EL1）
```

## IRQ domain 层级

### gic_irq_domain_ops

GIC 根 domain 用 `irq_domain_create_tree()` 创建（radix tree 映射），ops 包含 `.map`/`.translate`/`.alloc`/`.free`/`.select`。

`gic_irq_domain_map()`（`drivers/irqchip/irq-gic-v3.c:1547`）按 INTID 范围决定 flow handler：

```c
	struct irq_chip *chip = &gic_chip;
	...
	if (static_branch_likely(&supports_deactivate_key))
		chip = &gic_eoimode1_chip;

	switch (__get_intid_range(hw)) {
	case SGI_RANGE:
	case PPI_RANGE:
	case EPPI_RANGE:
		irq_set_percpu_devid(irq);
		irq_domain_set_info(d, irq, hw, chip, d->host_data,
				    handle_percpu_devid_irq, NULL, NULL);
		break;

	case SPI_RANGE:
	case ESPI_RANGE:
		irq_domain_set_info(d, irq, hw, chip, d->host_data,
				    handle_fasteoi_irq, NULL, NULL);
		irq_set_probe(irq);
		irqd_set_single_target(irqd);
		break;

	case LPI_RANGE:
		if (!gic_dist_supports_lpis())
			return -EPERM;
		irq_domain_set_info(d, irq, hw, chip, d->host_data,
				    handle_fasteoi_irq, NULL, NULL);
		break;

	default:
		return -EPERM;
	}

	/* Prevents SW retriggers which mess up the ACK/EOI ordering */
	irqd_set_handle_enforce_irqctx(irqd);
```

对应关系：

| INTID 范围 | 类型 | flow handler | 理由 |
| :-- | :-- | :-- | :-- |
| 0-15 | SGI | `handle_percpu_devid_irq` | 每 CPU 私有，无需共享仲裁 |
| 16-31（+1056-1119 EPPI） | PPI | `handle_percpu_devid_irq` | 同上 |
| 32-1019（+4096- ESPI） | SPI | `handle_fasteoi_irq` | 共享，需要 fasteoi 的 mask/ack 时序 |
| 8192+ | LPI | `handle_fasteoi_irq` | 消息中断，边沿语义 |

`irqd_set_handle_enforce_irqctx()` 禁止软件 retrigger，因为 GIC 的 ACK/EOI 顺序敏感，乱序会破坏优先级栈。

`gic_irq_domain_translate()`（`drivers/irqchip/irq-gic-v3.c:1589`）把 DT 的三元组 `<type, num, flags>` 翻译成 hwirq：type 0 = SPI（hwirq = num + 32），type 1 = PPI（hwirq = num + 16）。单参数且 < 16 的形式用于 SGI。

ITS（Interrupt Translation Service）把"设备写一个地址 + 一个数据"翻译成"某个 CPU 上的某个 LPI"。它是 GICv3 支持 MSI 的核心。

### 命令队列

驱动把命令封装成 builder 函数，再由 `its_send_single_command()` 统一提交。几个关键命令（`drivers/irqchip/irq-gic-v3-its.c:1306` 起）：

```c

{

	desc.its_mapd_cmd.valid = !!valid;

}

static void its_send_mapti(struct its_device *dev, u32 irq_id, u32 id)
{

	desc.its_mapti_cmd.phys_id = irq_id;
	desc.its_mapti_cmd.event_id = id;

}
```

| 命令 | 作用 |
| :-- | :-- |
| MAPD | 把 DeviceID 绑定到 ITT（建立设备表项） |
| MAPC | 把 Collection 绑定到目标 redistributor |
| MAPTI | 把 EventID 映射到物理 LPI 号 + collection |
| MOVI | 把已映射的 EventID 迁移到另一个 collection（改 affinity） |
| DISCARD | 解除 EventID 映射并清 pending |
| INVALL | 使某 collection 的所有 LPI 配置缓存失效 |
| INV | 使单个 LPI 的配置缓存失效 |

命令块是 4 个 64 位字（`struct its_cmd_block`，`drivers/irqchip/irq-gic-v3-its.c:532`），每项 32 字节。队列大小固定 64K（`drivers/irqchip/irq-gic-v3-its.c:539`）：


即 2048 个命令槽位。提交命令时更新 `GITS_CWRITE` 写指针，ITS 硬件异步消费；驱动用 `its_wait_for_range_completion()` 轮询 `GITS_CREADR` 确认完成。

### LPI 分配与 domain alloc

LPI 号从一个全局空闲区间链表分配（`drivers/irqchip/irq-gic-v3-its.c:2081` 的注释）：

```c
/*
 * How we allocate LPIs:
 *
 * lpi_range_list contains ranges of LPIs that are to available to
 * allocate from. To allocate LPIs, just pick the first range that
 * fits the required allocation, and reduce it by the required
 * amount. Once empty, remove the range from the list.
 *
 * To free a range of LPIs, add a free range to the list, sort it and
 * merge the result if the new range happens to be adjacent to an
 * already free block.
 *
 * The consequence of the above is that allocation is cost is low, but
 * freeing is expensive. We assumes that freeing rarely occurs.
 */
#define ITS_MAX_LPI_NRBITS	16 /* 64K LPIs */
```

```c
	base_sgi = irq_domain_alloc_irqs(gic_data.domain, 8, NUMA_NO_NODE, &sgi_fwspec);
	if (WARN_ON(base_sgi <= 0))
		return;

	set_smp_ipi_range(base_sgi, 8);
```

注释解释了为什么只用 8 个（`drivers/irqchip/irq-gic-v3.c:92`）：另外 8 个可能被安全世界占用。发送由 `gic_ipi_send_mask()` → `gic_send_sgi()` 写 `ICC_SGI1R_EL1` 完成，目标用 affinity + target list 编码。

### CPU 热插拔与电源管理

- `gic_check_rdist()` 注册在 `CPUHP_BP_PREPARE_DYN`，在 CPU 上线前检查 redistributor 是否可用。
- `gic_starting_cpu()` 注册在 `CPUHP_AP_IRQ_GIC_STARTING`，重跑 CPU interface 初始化。
- `gic_cpu_pm_notifier()`（`drivers/irqchip/irq-gic-v3.c:1482`）在 CPU 掉电前保存 redistributor 状态、上电后恢复。

### KVM

`gic_of_setup_kvm_info()`（`drivers/irqchip/irq-gic-v3.c:2157`）把 GICD/GICR 的物理地址与中断号填进 `gic_v3_kvm_info`，供 KVM 的 vgic 驱动使用。`gic_irq_set_vcpu_affinity()`（`drivers/irqchip/irq-gic-v3.c:737`）配合 GICv4 把物理 LPI 转发给 vPE。

## 配置与调试

| 配置项 | 本树状态 | 影响 |
| :-- | :-- | :-- |
| `CONFIG_ARM_GIC_V3` | y | 本驱动编译 |
| `CONFIG_ARM_GIC_V3_ITS` | y | ITS/LPI/MSI 支持 |
| `CONFIG_ARM_GIC_V2M` | y | 无 ITS 时的 fallback MSI |
| `CONFIG_ARM_GIC_V5` | y | GICv5 支持（独立驱动） |
| `CONFIG_ARM64_PSEUDO_NMI` | **未启用** | 优先级掩码/伪 NMI 路径不生效 |
| `CONFIG_ACPI` | 未启用 | 走 DT 探测，`its_acpi_probe` 不执行 |

调试手段：

- **启动日志**：`GIC: Using split EOI/Deactivate mode`、`%d SPIs implemented`、`CPU%d: found redistributor %lx region %d:%pa` 可确认初始化路径。
- **`/proc/interrupts`**：显示每个 virq 的 chip 名（GICv3 / ITS）与各 CPU 计数。
- **`/sys/kernel/debug/irq/`**：genirq 的 debugfs 接口可查 domain 层级与 irq_data 标志。
- **启动参数 `irqchip.gicv3_nolpi`**（`drivers/irqchip/irq-gic-v3.c:1261`）：强制关闭 LPI，退回 GICv2m，用于排查 ITS 问题。
- **`gic_deactivate_unhandled()` 的 WARN**：出现 "Unexpected interrupt" 说明 domain 映射缺失或硬件报了未注册的 INTID。
